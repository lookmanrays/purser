# M4-B Git adapter preflight

Source base `d865971fa3da20d0b82fa7bc56ca1b24c080270b`. Local component work for M4-B began after the following disposable probe. The agreed gate interface also survives outside the checkout in the M4 development handoff.

**Risk and invariant.** R3. A new physical release of one immutable Git intent advances its specified branch from the expected commit and creates one protected intent receipt together. A cold reader needs a consistent view of the same repository and proof that every possible earlier writer has ceased. A retained, attributable receipt can prove application after another advance. Confirmed nonapplication additionally requires the old branch, complete protected history and zero corresponding transitions. An ambiguous observation stays pending.

**Operating feasibility passed on the reference host.** Apple Git 2.50.1 initialized a new bare repository with reftable. CPython 3.11.15 acquired an exclusive BSD flock on its open directory and passed that descriptor to a real `git update-ref --stdin` child. The child confirmed start and preparation of a two-ref transaction. After SIGKILL of its Python parent, a new shared observer lock failed while the child still lived. That child then committed, exited and released the inherited lock. The quiescent reader saw the target. Repeating the expected-old update and receipt creation returned 128. After the branch advanced again the protected receipt still named the original target. A missing ref returned 2 from `git show-ref --exists`. This qualifies the local filesystem and process model for the isolated fixture. Reftable publishes a ref-and-log transaction by replacing one stack list. Loose-file repositories have a different publication boundary. [Git reftable update transactions](https://git-scm.com/docs/reftable#_update_transactions) · [Git update-ref transactions](https://git-scm.com/docs/git-update-ref)

**Authority and structure.** M4-A owns the gate, immutable intent, fresh attempt, clock and grant. The M4-B broker receives an authorization callback that returns only after durable admission. Native Git owns both refs and the transaction reflogs. An independent M4-B observer acquires a nonblocking shared lock and uses read-only Git commands. Both use the canonical wire digest and typed commit grammar. Existing experiment readers are evidence participants with their own fixture and environment. Importing them would couple product authority to the experiment. The new product module has no dependencies on experiments or an external service.

**Resource and lifetime.** A trusted launcher supplies the logical repository name, allowed full branch, new private canonical directory, initial object and staged commits. Bootstrap imports objects without updating staging refs and records a qualified physical instance anchored in the initial branch reflog. Broker and observer reopen the same directory inode, validate its identity/configuration and use no actor-provided filesystem path or Git configuration. The exclusive directory lock precedes cutoff and remains open in every possibly mutating Git child until exit. Hooks, remote transports and background maintenance are disabled. The observer cannot create a missing lock file or repair Git state. The single trusted operator, its protected receipt retention, controlled processes and local storage are accepted M1–M5 constraints. A hostile process with the operator’s credentials, destructive storage rollback and power failure need separate qualification.

**Impact and failure surfaces.** Target and expected old are full repository-format commit OIDs. The broker checks the logical resource, live direct branch, ancestry and changed paths before the gate considers path grants. Introduced commits, both sides of renames and intermediate changes participate in path scope. Native CAS and receipt creation reject even an erroneous duplicate release. The ledger serializes revocation at authorization and excludes unresolved deliveries. A writer lost across the cutoff, an unreadable or contradictory receipt, a substituted instance, or an unfinished native transaction demands reconciliation. Historical ledger replay and status are read-side concerns of M4-A/C. The adapter opens new private fixtures only. Existing product and user refs require no migration or rollback.

**Planned boundary evidence.** Exercise actual guarded transactions and independent reflog counts, exact attempt attribution, later native advance, stale CAS, repeated authorization callback and redelivery; check undeclared paths, fake OIDs and physical binding substitution. Kill real broker processes before and after publication, hold a native child beyond broker death, and inspect both refs independently before allowing any further action. Verify conflicting/corrupt or missing evidence leaves a reason and no second effect. M4-C owns durable gate-to-Git joining and official E3 collection on the integrated candidate.

Activated engineering lenses are authority and concurrency, durable execution, contract propagation, trust, filesystem/process bootstrap, recovery and the new interface’s dependency direction. External tracker synchronization and deployed activation have no role in this local packet.
