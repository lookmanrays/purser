# P1-08b Git effect adapter

## Goal

A controlled local Git repository where an authorized intent moves a branch and writes a protected receipt in one reftable transaction, and an independent observer can prove what happened.

## Context

Spec: `git-effects-v1.md`. Requires Git 2.45 or newer and POSIX `flock` (Linux or WSL2).

## Design

- `Initialize` creates a new private bare reftable repository from a staging repository, imports the named commits, sets retention and creates the branch. It returns a binding whose digest is anchored in the first reflog entry.
- `Broker` holds an exclusive `flock` on the repository directory. `Prepare(intent)` returns `intent_digest`, `repository_instance` and `changed_paths`. `Dispatch` prepares again under the lock, calls the kernel authorization callback, and runs `git update-ref --stdin` with start, prepare and commit, moving the branch and creating the receipt ref together.
- The Git child inherits the lock. Hooks, remote transports and background maintenance are disabled, and commands run with the open directory as their working directory.
- `Observe(intent, attempt)` takes a shared non-blocking lock and returns the fifteen fields with `confirmed_happened`, `confirmed_absent` or `pending` and a reason.
- Fault hooks after authorization and after the write let tests interrupt the process deterministically.

## Out of scope

Kernel operators (P1-08a). Windows-native locking.

## Test plan

Success path; interruption after cutoff and before Git; interruption after Git; a concurrent writer; a replaced repository path; a rewritten reflog; an unfinished native lock. Skip with an explicit message when Git is older than 2.45.

## Acceptance criteria

- AC-1 A dispatched intent moves the branch and creates `refs/purser/receipts/<digest>` atomically, and both reflogs carry the digest and attempt.
- AC-2 After an interruption before Git runs, `Observe` reports `confirmed_absent` with `quiescent_no_application`.
- AC-3 After an interruption once Git has published, `Observe` reports `confirmed_happened` with `protected_receipt_verified`.
- AC-4 A busy writer, rewritten history, a replaced repository or a leftover lock gives `pending` with a specific reason.
- AC-5 A legitimate later branch advance still lets `Observe` attribute the original transition.
- AC-6 Replacing the registered path after authorization cannot redirect the write.

## Definition of done

Standard Definition of done. Tests run on Linux CI with Git 2.45 or newer.

## Escalate if

Reftable transactions on the CI Git version cannot publish both refs atomically.
