# P4-01 Generator tools

## Goal

Code generators wrapped as typed tools with contracts, so the planner can schedule them like workers at zero token cost.

## Context

Design: Tools and code generation table.

## Design

- A tool registry: each tool has a contract file under `contracts/tools/` (inputs, outputs, effects, deterministic flag, cost) and a Go runner.
- v1 tools: `oapi-codegen`, `openapi-typescript` or `orval`, `sqlc`, `buf generate`, `gqlgen`, `mockery`, `go-jsonschema`, `json-schema-to-typescript`, `gofmt` and `goimports`, `prettier`.
- Runners check the tool version, run in the sandbox with only declared inputs mounted, and return the list of written files with digests.
- Determinism: running a deterministic tool twice gives identical outputs; a difference is reported.

## Out of scope

Language-server edits (P4-05 uses P2-04 directly).

## Test plan

A fixture input per tool with golden outputs; version detection; a missing tool.

## Acceptance criteria

- AC-1 Every tool contract validates against the tool contract schema.
- AC-2 Each tool's fixture produces its golden outputs.
- AC-3 A tool writing outside its declared outputs fails.
- AC-4 A missing tool fails with `tool_missing` and an install hint.

## Definition of done

Standard Definition of done.

## Escalate if

A tool cannot run without network access.
