# P5-05 Leaf bench

## Goal

At least 100 function contracts with tests, taken from your own Go and TypeScript projects, plus a harness that measures which model tier passes first time and at what cost.

## Context

Design: Evaluation (Leaf bench). The fixtures can start right after P0; measurements wait for the leaf loop (P4-05). Split before ready: fixtures in batches of about 25, and the harness.

## Design

- Each item: a function contract with examples, frozen tests, the surrounding package at a pinned commit with the function body removed, and the original body as reference (never shown to the model).
- Mix: pure functions, I/O wrappers, parsing, concurrency, HTTP handlers and React hooks; difficulty labels.
- Harness: run the leaf loop per item per tier, three attempts each, and record pass, attempts, tokens, cost and time.
- Output: per contract kind, first-pass rate and cost per tier; the router's default tiers come from it.

## Out of scope

Feature-level benchmarks (P5-06).

## Test plan

Harness tests on three tiny items with a fake model.

## Acceptance criteria

- AC-1 At least 100 items, each with a contract that validates and tests that fail on a stub and pass on the reference body.
- AC-2 The harness reports first-pass rate and cost per tier per contract kind.
- AC-3 No item's reference body appears in any context pack.

## Definition of done

Standard Definition of done. Split into fixture batches before ready.

## Escalate if

Your projects cannot supply enough functions of a kind.
