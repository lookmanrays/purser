# P3-07 Validator: compile check

## Goal

Check 10: before any model writes a body, the plan becomes a compiling skeleton whose tests all fail on the stubs, proven in a container.

## Context

Design: Definition of done for planning, check 10, "the strongest".

## Design

- `internal/sandbox`: run a command in a Docker container with the worktree mounted, network off, CPU and memory limits, a timeout and captured output. P4-02 extends it with worktrees.
- Compile check: copy the base commit into a temporary worktree, write generated stubs and skeletons, then run `go build ./...` and `go test` (or `tsc --noEmit` and `vitest run`) for the affected packages.
- Pass when the build succeeds and every generated test fails with `unimplemented`; a test that passes on a stub is reported as vacuous.
- Report findings in the validator's report format under check 10.

## Out of scope

Running real implementations.

## Test plan

Fixture plans: one valid, one with a type error in a contract, one with a vacuous test. Docker-dependent tests skip with a clear message when Docker is missing.

## Acceptance criteria

- AC-1 The valid fixture passes check 10.
- AC-2 The type-error fixture fails with the compiler output attached.
- AC-3 A test that passes on a stub is reported as vacuous.
- AC-4 The container has no network access and is removed after the run.

## Definition of done

Standard Definition of done.

## Escalate if

Docker on WSL2 cannot mount the worktree with acceptable speed.
