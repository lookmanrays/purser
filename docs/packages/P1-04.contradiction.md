# P1-04 contradiction: unspecified `Binding.Witness` encoding, `ops-work.yaml` error/op mismatches, and missing `WorkSpec` schema

## What is wrong

Frozen tests for P1-04 cannot be written from the contracts and brief without inventing unspecified wire formats and choosing between contradictory error codes across four points:

1. **`gate.Binding.Witness` (`map[string][]byte`) has no specified keys or encodings for structured `observer` (`candidate`) or `verifier` (`criterion`) fields.**
   - `Binding.Attachments` is restricted to `Role == "launcher"`, leaving `Binding.Witness` (`map[string][]byte`) as the only channel for `observer` and `verifier` bindings.
   - For `observation.record`, the reference passes a structured JSON object for `candidate`, whereas Go's `Witness` maps string keys to `[]byte`. Neither `gate.yaml`, `ops-work.yaml`, nor `P1-04.md` specifies whether `Witness["candidate"]` carries JSON bytes (and whether canonical encoding is required).
   - For `obligation.set` with `Role == "verifier"` (trusted verifier enrollment), the reference passes a `criterion` object containing `work` (string), `observer` (string), `definition` (bytes), and `environment` (bytes). Go's `Binding` has no `Criterion` field, and no contract specifies the keys or byte encoding inside `Witness` (for example, `"work"` and `"observer"` as raw UTF-8 vs JSON strings, or a `"criterion"` JSON object).

2. **`contracts/kernel/ops-work.yaml` contradicts `work-v1.md` and `workops.py` on `run.open` vs `observation.record` and on `digest_mismatch` vs `witness_mismatch`.**
   - `ops-work.yaml` puts `"freezes candidate, definition and environment identities from witness bytes"` and `errors: [forbidden, digest_mismatch, invalid_op, invalid_transition]` on `run.open`, whereas in `work-v1.md` and `workops.py` `run.open` has no witness bytes (it freezes identities from `Obligation` and `Result` records) and `observation.record` is the op that receives witness bytes and verifies digests.
   - `workops.py` rejects mismatched witness bytes/candidate in `observation.record` and mismatched observation-run binding in `evidence.record` with `witness_mismatch`, and rejects mismatched verifier enrollment `criterion` digests in `obligation.set` with `forbidden`. Meanwhile `ops-work.yaml` and `gate.yaml` omit `witness_mismatch` and define `digest_mismatch` (`"witness bytes do not match declared digests"`). Frozen tests for AC-4 ("a mismatched definition digest") cannot determine which code to assert.

3. **AC-4 ("Witness bytes over 8 MiB ... are rejected") vs `gate.go` (`unauthenticated` error, no receipt) vs `artifacts.yaml` (`too_large`).**
   - `internal/kernel/gate/gate.go` (matching reference `gate.py`) rejects `len(proof) > 8*1024*1024` during `authenticate(b)` with `*codec.Error{Code: "unauthenticated"}` (no receipt written), while `artifacts.Store.Put` returns `too_large`. Clarifying that AC-4 expects `unauthenticated` from `Gate.Admit` and `too_large` from `artifacts.Store.Put` (rather than a `ProposalReceipted` rejection) prevents ambiguity.

4. **`contracts/records/WorkSpec.schema.json` does not exist on `main` yet (P0-03), and `WorkSpecSet` event details are incomplete.**
   - `P1-04.md` and `ops-work.yaml` say `work.spec` validates `spec` against the `contracts/records` `WorkSpec` schema and emits `WorkSpecSet {id, spec}`. Only `contracts/records/records.draft.yaml` exists on `main`, leaving `WorkSpec` constraints (`required` fields, `budget` integer bounds, `@version` / glob / symbol-ID / obligation-ID string rules) and `WorkSpecSet` event version / `commitment` presence underspecified.

## Proposed fix

1. Specify in `contracts/kernel/gate.yaml` and `contracts/kernel/ops-work.yaml`:
   - The exact `Binding.Witness` keys and byte encodings for `observation.record` (`"candidate"` as JSON object bytes decoded with `codec.DecodeObject`, `"definition"`, `"environment"`, `"artifact"` as raw bytes) and for `obligation.set` verifier enrollment (`"work"` and `"observer"` as raw UTF-8 ID bytes, `"definition"` and `"environment"` as raw bytes — or add a dedicated representation if preferred).
2. Update `contracts/kernel/ops-work.yaml` (and `contracts/kernel/gate.yaml` if needed):
   - Move witness-byte verification and digest checking from `run.open` to `observation.record`.
   - Choose one error code (`digest_mismatch` or `witness_mismatch`) for mismatched witness bytes/candidate on `observation.record`, observation/run mismatch on `evidence.record`, and verifier enrollment mismatch on `obligation.set` (`forbidden` vs `digest_mismatch`).
3. Clarify in `docs/packages/P1-04.md` AC-4 that > 8 MiB witness bytes fail `Gate.Admit` with `unauthenticated` (no receipt, nothing stored) and `artifacts.Store.Put` with `too_large`.
4. Either merge `WorkSpec.schema.json` from P0-03 first or spell out the exact field/type/bound rules for `WorkSpec` and the exact `WorkSpecSet` event fields (`id`, `spec`, `EventVersion`, and whether `commitment` is included) in `contracts/kernel/ops-work.yaml`.
