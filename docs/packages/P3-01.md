# P3-01 Model gateway

## Goal

One Go interface over every model Purser uses, with per-role configuration, structured output, retries, prompt-prefix caching and a usage record for every call.

## Context

Design: Execution runtime (Model gateway) and Roles and model tiers. Roles never name a provider; configuration maps role and tier to a model. Bedrock access is employer-provided: you confirm it may be used before this package goes to ready.

## Design

- `Provider` interface: `Complete(ctx, Request) (Response, error)` and `Health(ctx)`. Providers in v1: Bedrock (Anthropic models through the Converse API), and OpenAI-compatible HTTP (Ollama, llama.cpp server, LM Studio, and any hosted compatible endpoint).
- `Request`: role, tier, system prompt split into a stable prefix and a variable part, messages, a JSON Schema for structured output, max tokens, temperature, deadline.
- Structured output: ask for JSON matching the schema, validate with `internal/schema`, and on failure retry once with the validation error attached. Then fail with `schema_violation`.
- Caching: the stable prefix is marked for provider-side prompt caching where supported (Bedrock cache points); providers without caching ignore the mark.
- Retries: exponential backoff with jitter on throttling and 5xx, at most three tries, within the deadline.
- `config/models.yaml`: providers, models, price per million input, output and cached tokens, and the role-to-tier-to-model map.
- Every call returns `Usage{input, output, cached, usd_micros, latency, provider, model}`. Writing it to the kernel is P5-04.
- Recording mode: `PURSER_MODEL_RECORD=dir` writes request and response pairs; `PURSER_MODEL_REPLAY=dir` serves them, so CI never calls a live model.

## Out of scope

Routing decisions (P5-02), local model management (P5-03) and cost records (P5-04).

## Test plan

Replay fixtures for both providers; an HTTP fake for OpenAI-compatible endpoints; throttling, timeouts and malformed JSON; price arithmetic.

## Acceptance criteria

- AC-1 A replayed Bedrock exchange returns the recorded response and usage.
- AC-2 A replayed OpenAI-compatible exchange returns the recorded response and usage.
- AC-3 Output that violates the schema is retried once with the error, then fails with `schema_violation`.
- AC-4 Throttling is retried with backoff at most three times and never past the deadline.
- AC-5 The stable prefix is sent with a cache mark on Bedrock and without one elsewhere.
- AC-6 `usd_micros` equals the configured prices times the token counts, rounded half up.
- AC-7 With replay mode on, no network connection is opened.

Bedrock access is not confirmed for this project, or a provider cannot return token counts.
