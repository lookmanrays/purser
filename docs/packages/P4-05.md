# P4-05 Leaf loop

## Goal

Purser's own minimal implementer: build the context pack, ask for a function body or patch as structured output, apply it, compile, test and lint in the worktree, retry within budget, then submit the candidate.

## Context

Design: Execution runtime (Leaf loop) and escalation rules.

## Design

- Output schema: either `{file, symbol, body}` replacing one function body, or a unified diff limited to the write scope.
- Apply, then run build, the node's tests and lint in the sandbox.
- On failure, attach compiler and test output (trimmed) and retry; three attempts per tier, then return `escalate` with the failures for the router.
- On success, commit in the worktree and submit `result.submit` with the commit as candidate.
- Every attempt is recorded with its usage.

## Out of scope

Tier choice (P5-02).

## Test plan

Replay fixtures for a leaf that passes first time, passes on the third attempt, and fails three times; a patch writing outside scope.

## Acceptance criteria

- AC-1 A first-time pass submits a candidate after one model call.
- AC-2 Failures are retried with the errors attached, at most three times per tier.
- AC-3 After three failures the loop returns `escalate` with all failure outputs.
- AC-4 A patch outside the write scope is rejected before it is applied.
- AC-5 Each attempt's usage is recorded.

## Definition of done

Standard Definition of done.

## Escalate if

Structured output is unreliable for a model tier on the fixtures.
