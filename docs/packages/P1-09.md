# P1-09 Kernel CLI

## Goal

`purser init`, `propose`, `status`, `why`, `replay`, `frontier`, `context` and `graph --work`, with machine output that matches the frozen shapes and exit codes.

## Context

Spec: `kernel-v1.md`, CLI surface and no-model answers. Schemas from P0-05.

## Design

- Global `--db PATH`, read options `--revision N` and `--as-of TIME`, and `--json` (the default for machine use) or `--text`.
- The human CLI is bound to `principal:local`. No flag or JSON chooses identity.
- Replies are one JSON object plus a newline; failures use the error envelope; exit codes follow `contracts/cli/exit-codes.yaml`.
- `graph --work` prints the work tree as text, DOT or JSON.
- Every command answers with no model and no network.

## Out of scope

Later commands (index, plan, run, cost, serve), which their own packages add.

## Test plan

Golden files from `wire-v1.json` expected replies; each exit code; a missing store; a mid-batch revision; `--as-of` reporting; schema validation of every reply.

## Acceptance criteria

- AC-1 `init`, `status --revision N`, `why` and `replay --as-of` reproduce the wire vector's expected replies, ignoring key order.
- AC-2 Every reply validates against its P0-05 schema.
- AC-3 Each failure class returns its specified exit code and error code.
- AC-4 Without `--as-of`, the reply reports the single clock sample used.
- AC-5 No command can act as an actor other than `principal:local`.
- AC-6 `graph --work` produces valid DOT and JSON for the lifecycle fixture.

## Definition of done

Standard Definition of done.

## Escalate if

A frozen reply shape cannot be produced from the public store, gate and view interfaces.
