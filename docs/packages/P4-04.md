# P4-04 Scheduler

## Goal

Run ready nodes in waves: nodes whose dependencies closed and whose contracts are frozen, grouped so write scopes never overlap, within budgets and parallelism limits.

## Context

Design: Execution runtime (Scheduler).

## Design

- Ready set from the kernel frontier: `assign` actions on work whose dependencies are closed and whose contracts are accepted.
- Wave building: greedy by priority (critical path length, then ID), adding a node only if its write globs do not intersect any node already in the wave; glob intersection is computed conservatively.
- Limits: parallel workers, GPU slots for local models, API rate per provider and the task budget.
- Each start is `work.assign` plus `assignment.dispatch` through the gate; each finish arrives as `result.submit` from the worker.
- Restart-safe: on start, the scheduler derives running and pending nodes from the kernel; it holds no state of its own.

## Out of scope

Workers (P4-05, P4-09) and integration (P4-07).

## Test plan

Fixture work graphs: chains, diamonds, overlapping scopes, budget exhaustion, restart mid-wave.

## Acceptance criteria

- AC-1 No two nodes in a wave have intersecting write scopes.
- AC-2 A node starts only after all its dependencies closed.
- AC-3 Parallelism and GPU limits are never exceeded.
- AC-4 When the budget is exhausted, no new node starts and the task reports `budget_exhausted`.
- AC-5 After a restart, the scheduler resumes from kernel state without duplicating dispatches.

## Definition of done

Standard Definition of done.

## Escalate if

Glob intersection cannot be decided conservatively for a scope pattern.
