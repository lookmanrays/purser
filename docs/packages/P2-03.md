# P2-03 Syntax fallback

## Goal

Files, top-level declarations and imports for Go and TypeScript when no SCIP index is available, so the graph is never empty.

## Context

The design planned tree-sitter here. Its Go bindings need cgo, and the build is cgo-free (`modernc.org/sqlite`). This package therefore uses Go's own `go/parser` for Go and the TypeScript compiler API through a small bundled Node script for TypeScript. Tree-sitter can be added later behind the same interface if cgo becomes acceptable.

## Design

- Go: `go/parser` with comments; nodes for files, packages, functions, methods, types, constants and variables with ranges, signatures printed by `go/printer`, and doc comments; `imports` edges.
- TypeScript: `syntax/ts/extract.mjs` (bundled with `go:embed`) runs under `node` and uses the `typescript` package from the target repository's `node_modules`. It prints one JSON object per file with declarations, export flags, signatures and imports.
- Symbol IDs use the prefix `sym:syntax:` plus language, path and qualified name, so they never collide with SCIP IDs.
- Every node and edge carries `source: syntax`.

## Out of scope

References and type resolution.

## Test plan

Golden extraction for the P2-02 fixture repositories. A TypeScript repository without `typescript` installed. Syntax errors in one file.

## Acceptance criteria

- AC-1 The Go fixture yields the declarations and imports in its golden file.
- AC-2 The TypeScript fixture yields the declarations, export flags and imports in its golden file.
- AC-3 A file with a syntax error yields a file node with an `error` field and does not stop the rest.
- AC-4 Without `typescript` in the repository, TypeScript extraction fails with `typescript_missing` and Go extraction still runs.
- AC-5 Syntax IDs never equal any SCIP ID from the same fixture.

## Definition of done

Standard Definition of done.

## Escalate if

Go and TypeScript extraction cannot share one batch format.
