# P0-06 Conformance vectors and golden logs

## Goal

purser-main's frozen vectors, plus golden event logs recorded from its own test scenarios, are available to Go tests byte-identically, with a typed loader and a manifest that proves they never drift.

## Context

The Go kernel must reproduce purser-main's bytes, hashes and projections exactly. The frozen vectors cover M1 in full but later milestones only at checkpoints, and they contain records of only three kinds. Golden logs from the reference scenarios cover every v1 record kind and event type.

## Design

Frozen vectors:

- Copy `wire-v1.json`, `lifecycle-v1.json` and `m2-legacy-status-v1.json` from `reference/python/docs/contracts/` to `testdata/vectors/purser-v1/` unchanged.
- `testdata/vectors/MANIFEST.sha256` lists the SHA-256 of every file under `testdata/vectors/`; a CI job checks it.
- `testdata/vectors/README.md` maps each vector section to the packages that must pass it: encoding and events to P1-01, batches to P1-02a, admission replies and independent cases to P1-03, the lifecycle trace to P1-04 through P1-08b, CLI replies to P1-09.

Golden logs:

- `tools/refdump/refdump.py` runs a fixed list of reference test methods from `tests/test_gate.py`, `tests/test_work.py`, `tests/test_decisions.py` and `tests/test_effects.py` (named in `tools/refdump/scenarios.txt`).
- It records every reference `Store` the scenario opens: after the test it reads the stored event bodies in revision order and the snapshot at each batch boundary.
- Output per scenario under `testdata/vectors/golden/<test_name>/`: `events.jsonl` (exact stored bytes, one event per line), `snapshots.jsonl` (`{revision, head_hash, projection_checksum, projection}` per batch) and `meta.json` (scenario name, reference Git commit, Python version).
- It runs with `python -I` from the repository root, needs Git 2.45 or newer for the effect scenarios, and is deterministic: two runs produce identical files.
- `make golden` regenerates the files; CI fails if a regeneration differs from what is committed.

Loader:

- `internal/testvectors` is a test-only helper: `Wire()`, `Lifecycle()`, `LegacyStatus()` return typed structs for the top-level sections, `Golden(name)` returns a scenario's events and snapshots, `GoldenNames()` lists them, and `Raw(path)` returns exact bytes.

## Out of scope

No new hand-written vectors. New cases belong to each package's test author.

## Test plan

Check the manifest. Check that loader structs expose each section. Check that golden events form a valid chain by comparing each `prev_hash` with the previous line's `hash`, without re-hashing (hashing is P1-01's job). Check that every v1 record kind listed in `records.draft.yaml` appears in at least one golden snapshot.

## Acceptance criteria

- AC-1 The three frozen files are byte-identical to the reference copies, and the manifest proves it.
- AC-2 The loader exposes every top-level section of `wire-v1.json`: contract, actor, clock_by_batch, encoding_vector, proposals, request_digests, events, expected, legacy, independent_case_branches and binding.
- AC-3 The loader exposes the lifecycle trace's steps, outcome vectors and overlays.
- AC-4 Golden logs exist for at least 20 scenarios and together contain all sixteen v1 record kinds.
- AC-5 Running `make golden` twice gives identical files.
- AC-6 CI fails if any file under `testdata/vectors/` changes without a manifest update.

## Definition of done

Standard Definition of done.

## Escalate if

The reference checker fails on the copied files, or a scenario cannot be recorded without changing reference code.
