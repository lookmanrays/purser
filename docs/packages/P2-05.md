# P2-05 Incremental update

## Goal

After a merge, update only what changed: the files in the diff and the packages that depend on them, with a correct final graph.

## Context

The gate for P2 says an incremental update must be clearly faster than a full index. Workers and observers run after every merged wave, so this matters at P4.

## Design

- Input: the indexed commit from store metadata and a new commit. Changed files come from `git diff --name-status` between them, with renames handled as delete plus add.
- Affected set: changed files, plus files in packages that import a changed package (from `imports` edges), up to the contract's limit. Beyond that limit, fall back to a full index.
- Re-index the affected set: restrict the SCIP run to affected packages when the indexer supports it (P2-02 records whether it does); otherwise run the indexer fully but load only the affected documents.
- Replace affected files through `store.Replace`, then repair dangling edges by dropping edges whose targets no longer exist.
- Record the new commit, the mode (`incremental` or `full`) and the affected-file count in metadata.
- Equivalence rule: after an incremental update, the digest equals the digest of a full index at the same commit.

## Out of scope

Background or continuous indexing (the daemon, P6-05).

## Test plan

A fixture Git repository with a scripted series of commits: edit a function body, rename a symbol, delete a file, add a package, change an interface used elsewhere. After each commit compare incremental and full digests. Benchmark one-file changes on the fixture.

## Acceptance criteria

- AC-1 After each scripted commit, the incremental digest equals the full-index digest at that commit.
- AC-2 A rename is handled as a delete plus an add, and no edge points to the old path.
- AC-3 When the affected set exceeds the limit, the update runs as a full index and records mode `full`.
- AC-4 No dangling edges remain after an update.
- AC-5 A one-file body change on the fixture updates at least five times faster than a full index, under `benchcheck`.

## Definition of done

Standard Definition of done.

## Escalate if

Digest equivalence fails for a case the indexers themselves treat differently in partial runs.
