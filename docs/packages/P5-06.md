# P5-06 Feature, trap and recovery benches

## Goal

The fixtures and harness that compare Purser with baselines B1 and B2 on delivered changes: features, traps and recovery after kills and model swaps.

## Context

Design: Evaluation. You run the baselines. Split before ready: feature fixtures, trap fixtures, recovery harness, baseline harness.

## Design

- Feature bench: 10 to 20 multi-module features from your projects, each with acceptance tests and a pinned base commit.
- Trap bench: features with conflicting tests, skipped requirements, helpers to reuse and layer rules to respect.
- Recovery bench: runs killed mid-wave and a model swapped mid-task; success means the run resumes from kernel state.
- Baselines: B1 is Claude Code or Codex with AGENTS.md, an execution plan and CI on one strong model; B2 adds an independent verifier running Purser's checks.
- Metrics per run: accepted, false done, out-of-scope edits, duplicates, layer violations, tokens and price by role, human minutes, wall-clock, rework after acceptance.

## Out of scope

Router learning (P5-07).

## Test plan

Harness tests on a tiny fixture feature with scripted outcomes.

## Acceptance criteria

- AC-1 At least 10 feature, 5 trap and 3 recovery fixtures, each with acceptance tests that fail at the base commit.
- AC-2 The harness records every listed metric for Purser, B1 and B2.
- AC-3 Results are reported even where the baseline ties.

## Definition of done

Standard Definition of done, plus your baseline runs.

## Escalate if

A fixture's acceptance tests pass at its base commit.
