# P1-02b verification boundary conflict

## What conflicts

[P1-02b](P1-02b.md#design) requires `Snapshot(nil)` to read the materialized
tables and check the stored head against the last event. It also requires
`Transact` to start from materialized state under write ownership. AC-4 caps
the cost of a head read as history grows. The
[store contract](../../contracts/kernel/store.yaml#L56-L87) assigns chain
verification to `Initialize` on an existing database and to `Verify` in
P1-02c.

[The inherited P1-02a tests](../../internal/kernel/store/integrity_test.go#L23-L94)
require `Snapshot(nil)` to report the first damaged historical revision as
well. The trailing-bytes case updates only the body of revision 1 in a
two-event log. The materialized tables, head metadata, and last event are
identical before and after that update. The inputs to the specified head check
therefore cannot distinguish the damaged database from the clean one. Checking
only the current batch would have the same limitation for older batches.

[The missing-receipts case](../../internal/kernel/store/integrity_test.go#L128-L156)
also expects both `Snapshot(nil)` and `Transact` to reject a well-formed but
incomplete materialization. The surviving rows and a matching event head do
not establish that all expected receipts are present. Today the fold supplies
that evidence.

Both tests came from P1-02a. Its brief does not list them as frozen, but the
[builder playbook](../agents/builder.md#playbook-builder) forbids changing
existing tests and the standard definition of done requires the full race
suite. Continuing to fold on every head read also fails AC-4.

## Evidence

Unchanged baseline `frozen/P1-02b` (`ac4d3d2`), Go 1.27.4 on darwin/arm64.

- `go test ./internal/kernel/store -run '^TestAC4_HeadSnapshotTimingRatio$' -count=1 -v`
  failed at **10.72×** (limit **2×**). The medians for 25 reads were
  **211.581 ms** at 1,000 events and **2.268006167 s** at 10,000.
- `go test ./internal/kernel/store -run '^(TestSnapshotRejectsDamagedHistoryAtFirstRevision|TestStoreRejectsDamagedMaterializedRowsBeforeDeciding)$' -count=1`
  passes with the existing fold. Those tests exercise both conflicting
  expectations directly against SQLite.

## Proposed resolution

Confirm where full-history and projection completeness checks belong. If the
current design is authoritative, explicitly authorize retargeting the inherited
full-verification assertions to `Initialize`, and to `Verify` once P1-02c
ships. Keep the checks for the first bad revision, missing rows, and exact
fold equality. Keep separate head-path checks for a mismatched checkpoint,
malformed row bodies and incorrect row keys, and keep the historical
batch-boundary checks. All frozen tests can stay byte-identical.

If missing rows must fail closed before each decision or every head read must
report the earliest damaged historical event, specify the corresponding
integrity mechanism and its existing-database behavior before implementation.
The current checkpoint and table layout do not supply those guarantees at the
specified read boundary.
