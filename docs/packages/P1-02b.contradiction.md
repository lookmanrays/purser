# P1-02b Contradiction Escalation

## 1. Contradiction: `briefcheck red` fails on already-passed tests from ancestor packages in the same package directory

### What is wrong

Package P1-02b is the first package in the repository that writes to a package directory (`internal/kernel/store`) where an ancestor package (`P1-02a`) has already merged into `main` with its own frozen tests (`store_test.go`, `transact_test.go`).

When `make red ID=P1-02b` is executed on `tests/P1-02b`, it fails immediately with:
```
error: test TestAC1_TransactWireBatchesReplay passed on stubs unexpectedly (action: pass)
exit status 1
make: *** [red] Error 1
```
even when all new tests written for P1-02b in `tests_frozen` (`snapshot_test.go`, `snapshot_bench_test.go`) fail on stubs.

### Evidence

In `tools/briefcheck/main.go`, `Red()` collects package directories from `b.TestsFrozen`, but then runs and checks **all** `TestAC*` tests across the entire package directory:
```go
// Red lists TestACn_ functions, verifies all ACs are covered, runs them, and passes only if all fail.
func Red(repoRoot, id string) error {
    ...
    testACMap, pkgDirs := make(map[string]bool), make(map[string]bool)
    _ = filepath.Walk(repoRoot, func(path string, info os.FileInfo, err error) error {
        if err == nil && !info.IsDir() && strings.HasSuffix(path, "_test.go") {
            if rel, _ := filepath.Rel(repoRoot, path); matchesAny(rel, b.TestsFrozen) {
                pkgDirs[filepath.Dir(path)] = true
                data, _ := os.ReadFile(path)
                for _, m := range reTest.FindAllStringSubmatch(string(data), -1) {
                    testACMap[m[1]] = true
                }
            }
        }
        return nil
    })
    ...
    for pkgDir := range pkgDirs {
        relPkg, _ := filepath.Rel(repoRoot, pkgDir)
        cmd := exec.Command("go", "test", "-json", "-run", `^TestAC[0-9]+_`, "./"+relPkg)
        cmd.Dir = repoRoot
        out, _ := cmd.CombinedOutput()

        topLevel := make(map[string]string)
        for _, line := range strings.Split(string(out), "\n") {
            var ev struct{ Action, Test string }
            if json.Unmarshal([]byte(strings.TrimSpace(line)), &ev) == nil && ev.Test != "" && !strings.Contains(ev.Test, "/") && strings.HasPrefix(ev.Test, "TestAC") && (ev.Action == "pass" || ev.Action == "fail" || ev.Action == "skip") {
                topLevel[ev.Test] = ev.Action
            }
        }
        ...
        for name, act := range topLevel {
            if act != "fail" {
                return fmt.Errorf("test %s passed on stubs unexpectedly (action: %s)", name, act)
            }
        }
    }
    return nil
}
```

Notice:
1. `pkgDirs` contains `internal/kernel/store`.
2. `cmd := exec.Command("go", "test", "-json", "-run", `^TestAC[0-9]+_`, "./"+relPkg)` runs all `TestAC` functions in `./internal/kernel/store`.
3. Because `P1-02a` merged into `main`, `./internal/kernel/store` contains `TestAC1_TransactWireBatchesReplay`, `TestAC2_SnapshotRevisionsAndProjectionHashes`, `TestAC3_FaultAfterInsertLeavesStateUnchanged`, `TestAC4_DecideErrorRollsBackNoPartialRows`, `TestAC5_EmptyEventListChangesNothing`, `TestAC6_TransactUnregisteredEventFails`, and `TestAC7_FreshStoreZeroHeadEmptyProjection`.
4. All 7 tests from P1-02a pass on `main`.
5. `Red()` iterates over all tests in `topLevel` and rejects any test that did not fail (`if act != "fail"`), mistakenly failing on P1-02a's already-passing tests.
6. Per `AGENTS.md` Rule 1 and Rule 2, the test author cannot edit frozen tests (`tests_frozen` of P1-02a). Nor can the test author modify `tools/briefcheck` because it is outside P1-02b's `scope.write`.

### Proposed Fix

In `tools/briefcheck/main.go`, `Red()` should only verify that the tests declared in the brief's own `tests_frozen` fail on stubs.

Specifically:
During the `filepath.Walk` phase, record the set of test names declared in `b.TestsFrozen`:
```go
    thisBriefTests := make(map[string]bool)
    _ = filepath.Walk(repoRoot, func(path string, info os.FileInfo, err error) error {
        if err == nil && !info.IsDir() && strings.HasSuffix(path, "_test.go") {
            if rel, _ := filepath.Rel(repoRoot, path); matchesAny(rel, b.TestsFrozen) {
                pkgDirs[filepath.Dir(path)] = true
                data, _ := os.ReadFile(path)
                for _, m := range reTest.FindAllStringSubmatch(string(data), -1) {
                    testACMap[m[1]] = true
                }
                for _, line := range strings.Split(string(data), "\n") {
                    if strings.HasPrefix(strings.TrimSpace(line), "func TestAC") {
                        name := strings.TrimPrefix(strings.TrimSpace(line), "func ")
                        if idx := strings.Index(name, "("); idx != -1 {
                            thisBriefTests[strings.TrimSpace(name[:idx])] = true
                        }
                    }
                }
            }
        }
        return nil
    })
```
Then, when checking `topLevel`:
```go
    for name, act := range topLevel {
        if !thisBriefTests[name] {
            continue
        }
        if act != "fail" {
            return fmt.Errorf("test %s passed on stubs unexpectedly (action: %s)", name, act)
        }
    }
```
Or construct the `-run` regex pattern passed to `go test` using the exact test names in `thisBriefTests`.

## 2. Contradiction: Incremental packages without contract changes cannot stub existing methods

### What is wrong

Package P1-02b specifies:
- `contract: contracts/kernel/store.yaml@v1`
- `contract_change: false`
- `depends_on: [P1-02a]`

Every Go declaration in `contracts/kernel/store.yaml@v1` (`Store`, `Snapshot`, `Transact`, `Events`, `RawEvents`, etc.) was already declared and implemented in `internal/kernel/store` by P1-02a.

Per `docs/agents/test-author.md`:
- "A stub holds exactly the contract's Go declarations, with blank parameter names (`_`) and a doc comment on every exported identifier. Bodies call a panicking function variable..."
- "every TestACn_ test must FAIL, and only by 'unimplemented'"

However:
1. In Go, an existing package cannot redeclare existing methods (`func (s *Store) Snapshot(...)`) in a `zz_stub.go` file; the Go compiler rejects duplicate method declarations with `(*Store).Snapshot redeclared in this block`.
2. Because no new contract declarations exist, `zz_stub.go` cannot replace or stub `Snapshot`.
3. The baseline implementation of `Snapshot` implemented by P1-02a already folds the event log. Consequently, tests written for:
   - AC-1: After every wire vector batch, the materialized snapshot equals the from-scratch fold.
   - AC-3: A head-hash mismatch fails with `integrity_error`.
   - AC-5: A historical snapshot at a mid-batch revision fails with `bad_revision`.
   will pass against the P1-02a baseline implementation, violating the rule that all AC tests must fail on stubs.

### Proposed Fix

Clarify the test-author and freeze procedure for incremental packages refining existing packages:
1. When an incremental package modifies internal package performance/mechanics (such as P1-02b introducing materialized reads and incremental reducer writes to replace log folding) without altering the contract interface:
   - Allow an internal unexported stub hook (e.g. `snapshotMaterializedHook` or `zz_stub.go` setting an internal panicking stub function in `init()`) that causes calls to the unoptimized or new path to panic with `unimplemented: <ID>`.
   - Or update `make red` to permit tests that assert new performance/behavior criteria (e.g. AC-4 benchmark ratio fails on the baseline quadratic replay) while acknowledging that baseline behavior tests may pass against the ancestor implementation.
