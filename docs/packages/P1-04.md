# P1-04 Work model

## Goal

The work operators from purser-main's work contract, the SHA-256 artifact store, and the v2 `work.spec` operator that gives a WorkItem its design fields.

## Context

Spec: `work-v1.md`. The design's WorkNode maps to WorkItem plus `spec`; see VOCABULARY.md.

## Design

- Operators: `work.create`, `work.coverage`, `work.assign`, `result.submit`, `obligation.set`, `run.open`, `observation.record`, `evidence.record` and `obligation.waive`, with the fields, callers and effects in `work-v1.md`.
- `work.spec` (v2) has fields `id` and `spec`, per `records.draft.yaml`. Principal or planner only. It validates shape against the `WorkSpec` schema and stores it as `fields.spec` on the WorkItem. It is not enforced until P3 and P4.
- Observer and verifier bindings carry typed proofs, as `gate.yaml` now declares: `Binding.Witness` (candidate, definition, environment, artifact) for `observation.record`, and `Binding.Criterion` (work, observer, definition, environment) for trusted verifier enrollment in `obligation.set`. This package updates the gate's `Binding`, adds `ValidCandidate` and extends `authenticate`: shape and the 8 MiB limit fail with `unauthenticated` and no receipt. The operators check digests: `witness_mismatch` for `observation.record` and `evidence.record`, `forbidden` for enrollment, as `workops.py` does.
- `work.spec` validates in Go by the rules `ops-work.yaml` lists, which match P0-03's `WorkSpec.schema.json`. Kernel packages may not import `internal/schema`.
- The result producer can never be the observer or verifier of the same run.
- `internal/kernel/artifacts` stores bytes under their SHA-256 and verifies them on every read. Publication stages bytes before the reference is admitted. `*artifacts.Store` satisfies `gate.ArtifactStore`; assert it with `var _ gate.ArtifactStore = (*artifacts.Store)(nil)` in `internal/kernel/ops/work`, since `artifacts` may import only `codec`.
- The package registers reducers for every work event type and version in the reference `workevents.py` through `projection.Registry`.
- Redelivery re-checks prior access, as the reference's `gate._redelivery` does. Work operators are the first to need it, so this package adds the gate side: `gate.PriorAccess` in `internal/kernel/gate/prior_access.go`, and the call in the gate's redelivery branch. The work operators implement it as `workops.prior_work_access` does: the op must be bound to the binding, and an executor's `work.create` needs its assignment current for that parent at the receipt's revision.

## Out of scope

`work.close` and `work.accept` (P1-05). Invalidation (P1-06). Premise and Git proofs on bindings (P1-07, P1-08b). Adding `WorkSpecSet` to `contracts/records/event.schema.json` (a follow-up after P0-03 merges).

## Test plan

Scenario tests for the lifecycle trace up to, but not including, closure. Use `evidence_bindings` for the exact tuple a verdict binds to. Add negatives: a producer acting as observer, a witness over 8 MiB, a mismatched definition digest, a result on a stale assignment, and a malformed `spec`.

## Acceptance criteria

- AC-1 The lifecycle steps before closure produce the receipts and record fields the trace requires.
- AC-2 A verdict binds exactly the tuple in `evidence_bindings`.
- AC-3 A run whose observer or verifier is the result producer is rejected with `forbidden`.
- AC-4 A witness byte field over 8 MiB fails `Admit` with `unauthenticated` and no receipt. A definition or environment whose SHA-256 differs from the run's gives a rejected `witness_mismatch` receipt. In both cases nothing is written to the artifact store.
- AC-5 Reassignment advances the generation and clears the previous result and candidate.
- AC-6 `work.spec` stores a valid spec and rejects an invalid one with `invalid_op`.
- AC-7 An artifact whose bytes were altered on disk fails verification on read.
- AC-8 Folding each golden log from `tests/test_work.py` through the registered reducers reproduces every recorded snapshot.
- AC-9 Redelivery re-checks prior access with the redelivering binding (which can differ from the original; only the actor ID is in the digest): an executor whose binding names an assignment that was not current for that parent at the receipt's revision gets `unauthenticated` and nothing is appended, while the original binding gets the receipt back. Receipts with codes `bad_revision`, `invalid_op`, `unknown_op`, `forbidden` and `not_found` skip the check.
