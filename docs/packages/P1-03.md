# P1-03 Gate

## Goal

The single admission path: bindings from trusted ingress, envelope checks, idempotent receipts, stale-base detection from read dependencies, an operator registry, and the M1 operators.

## Context

Spec: `kernel-v1.md`, Admission and durable outcomes, and the M1 operators table.

## Design

- `Admit(binding, proposal)` returns the durable receipt, or a typed error only for failures that leave no receipt (`invalid_input`, `unauthenticated`, `unavailable`, `integrity_error`).
- Order of checks: identity and deduplication, then base validity, then per-op syntax and authorization, then read conflicts, then lifecycle and time.
- Deduplication on (actor, proposal ID): the same digest returns the latest receipt; a changed digest returns `id_conflict` with no event.
- Operators register with `Register(name, Operator)`. Each operator validates its fields, authorizes against the binding, records reads in a ReadSet (records, collections and absences) and returns events against a tentative state.
- Stale base: a read dependency changed after the base gives `stale_base` with conflicts sorted by key. Unrelated changes do not stale a proposal.
- A rejected multi-op batch writes only its receipt.
- `RegisterM1` adds `commitment.create`, `commitment.edit`, `commitment.request_acceptance` and `approval.answer`.
- Bindings never come from proposal JSON.

## Out of scope

Work, decision and effect operators (P1-04, P1-07, P1-08a).

## Test plan

Reproduce `expected.admission_replies` and every case in `independent_case_branches`. Add cases for redelivery, digest change, unrelated change versus read-dependency change, error precedence, approval expiry at exactly the deadline, and a multi-op batch failing on its second op.

## Acceptance criteria

- AC-1 Every admission reply in `wire-v1.json` is reproduced exactly, including revisions and details.
- AC-2 Every `independent_case_branches` case produces its expected outcome.
- AC-3 Redelivering the same request returns the same receipt and revision and appends nothing.
- AC-4 The same actor and proposal ID with a different digest returns `id_conflict` and appends nothing.
- AC-5 A change to a read dependency after the base gives `stale_base` with the right conflicts; an unrelated change does not.
- AC-6 When several errors apply, the code follows the specified precedence.
- AC-7 An approval answered at exactly its expiry resolves as expired.
- AC-8 A failing multi-op batch saves no domain events, only its receipt.

## Definition of done

Standard Definition of done.

## Escalate if

A case requires operators to read state outside what they declare in the ReadSet.
