# P5-01 Triage

## Goal

Classify every task into level 0 to 3 with a path and a budget, by rules first and a small model only when rules are unsure, with a human override.

## Context

Design: Routing and the cost model (levels table).

## Design

- Rules over the task text and a graph estimate of touched packages: rename, move, format or dependency bump gives level 0; one module gives level 1; a few modules gives level 2; cross-cutting or architectural keywords, or many modules, gives level 3.
- When rules disagree or confidence is low, a local model or Haiku classifies with the rule features as input.
- `purser triage <task>` prints level, path, budget and reasons; `--level N` overrides and is recorded as a principal decision.

## Out of scope

Tier selection inside a level (P5-02).

## Test plan

A labelled set of at least 40 task descriptions from your projects with expected levels; replay fixtures for the model.

## Acceptance criteria

- AC-1 At least 85% of the labelled set gets the expected level.
- AC-2 No labelled level 3 task is classified below level 2.
- AC-3 An override is recorded and takes effect.
- AC-4 Reasons list the rule or model that decided.

## Definition of done

Standard Definition of done.

## Escalate if

The labelled set shows levels the rules cannot separate.
