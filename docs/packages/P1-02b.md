# P1-02b Store: projection reads

## Goal

Reads at the head come from materialized projection tables in roughly constant time, which removes purser-main's quadratic replay.

## Context

purser-main refolded the whole log on every read: 125 ms at 1,000 events and 482 ms at 2,000. See the design's Kernel section.

This package extends the store built by P1-02a, which already folds correctly. AC-1, AC-2, AC-3 and AC-5 are marked `(baseline)`: they hold today and must keep holding. AC-4, read time independent of history length, is what changes.

## Design

- `Transact` starts from the materialized snapshot instead of a fold, and updates projection rows incrementally from the reducer's changes inside the same transaction.
- `Snapshot(nil)` reads the materialized tables and checks that `meta.head_hash` equals the hash of the last event. A mismatch fails with `integrity_error`.
- `Snapshot(&rev)` for an earlier revision folds events up to `rev`. That slower path is allowed and memoized per revision within a process.
- Reducers track changed records and edges, so a batch writes only its changed rows.

## Out of scope

Replay and verification (P1-02c).

## Test plan

Property test: after random valid batches, the materialized snapshot equals a fold from scratch, with equal checksums. Corrupt `meta.head_hash` and check the failure. For AC-4, build logs whose later events edit the same records, so the projection size is equal at every length, and compare the median of repeated head reads at 1,000 and 10,000 events. Add a benchmark of the same reads at 1k, 10k and 100k events with the ratio rule for `benchcheck`.

## Acceptance criteria

- AC-1 (baseline) After every wire vector batch, the materialized snapshot equals the from-scratch fold.
- AC-2 (baseline) After 1,000 random valid batches, the materialized projection checksum equals the fold checksum.
- AC-3 (baseline) A head-hash mismatch fails with `integrity_error`.
- AC-4 With the same final projection, a head snapshot over 10,000 events takes at most twice as long as over 1,000 events; the benchmark applies the same rule at 100,000 events under `benchcheck`.
- AC-5 (baseline) A historical snapshot at a mid-batch revision fails with `bad_revision`.

## Definition of done

Standard Definition of done.

## Escalate if

Incremental maintenance would require reducers to read outside the batch's own changes.
