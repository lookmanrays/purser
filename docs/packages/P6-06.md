# P6-06 ACP server

## Goal

Purser as an Agent Client Protocol agent, so Zed, JetBrains and Neovim can start tasks, show plans and progress, and request approvals.

## Context

Design: Architecture (Protocols) and Later: UI and inspirations.

## Design

- Implement the ACP agent side over stdio: session start, prompt, streamed updates and permission requests.
- A prompt becomes `task new` plus triage; plans and wave progress stream as updates; design approval maps to an ACP permission request answered by the user.
- Use an ACP Go library if a maintained one exists at ready time; otherwise implement the JSON-RPC methods from the specification.

## Out of scope

Editor-specific plugins.

## Test plan

A scripted ACP client exercising a task from prompt to approval to done in replay mode.

## Acceptance criteria

- AC-1 A scripted client can start a task and receive plan and progress updates.
- AC-2 Design approval through an ACP permission request admits the held plan.
- AC-3 Malformed client messages return protocol errors without crashing the daemon.

## Definition of done

Standard Definition of done.

## Escalate if

ACP cannot represent a held design approval.
