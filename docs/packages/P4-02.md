# P4-02 Worktrees and isolation

## Goal

One Git worktree per running node, with tests in containers and the kernel, frozen tests and credentials out of the worker's reach.

## Context

Design: Execution runtime (Worktrees, Isolation).

## Design

- `Create(node, base)` makes `.purser/worktrees/<node>-<generation>` on branch `purser/<node>/<generation>` from the integration branch at the plan base.
- Frozen test files are written read-only in the worktree, and the scope observer verifies them by digest.
- The worker process gets only the worktree path; the kernel database, artifact store and credential files are outside it and not mounted into containers.
- Containers: network off by default, per-node CPU and memory limits, the worktree mounted read-write, caches mounted read-only.
- `Remove(node)` cleans up after integration or abandonment; orphans are found and removed at startup.

## Out of scope

Merging (P4-07).

## Test plan

Create, run, remove; orphan cleanup; an attempt to read the kernel path from inside the container.

## Acceptance criteria

- AC-1 Each node gets its own worktree on the specified branch from the plan base.
- AC-2 A process inside the container cannot read the kernel database or credentials.
- AC-3 Frozen tests in the worktree are read-only, and a modification is detected by digest.
- AC-4 Orphaned worktrees are removed at startup.

## Definition of done

Standard Definition of done.

## Escalate if

Docker on WSL2 cannot enforce the mount restrictions.
