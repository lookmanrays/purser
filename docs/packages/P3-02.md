# P3-02 Context pack builder

## Goal

For any work item, a deterministic, size-limited context pack holding exactly what its role needs: task, contract, neighbours' interfaces, decisions, reuse targets, tests, allowed tools and budget.

## Context

Design: Execution runtime (Context pack) and the cost model. The pack replaces "read the repository" and is the main lever on cost and drift.

## Design

- `Build(workID, role, limits) (Pack, error)` reads the kernel snapshot (work spec, contract digest, decisions, obligations) and the graph store (interfaces of packages in `scope.read`, symbols in `reuse`, reuse-finder candidates for the contract).
- Sections in fixed order with per-section token limits; overflow trims lowest-priority items first and lists what was trimmed.
- Token estimate by a byte heuristic per model family, configurable.
- The pack is canonical JSON with a SHA-256 digest; the same inputs give the same digest.
- Role filters: a test author never receives implementation files or bodies; an implementer receives its tests' source.
- `Render(pack, format)` prints Markdown for models and JSON for tools.

## Out of scope

Model calls.

## Test plan

Fixture kernel snapshot plus fixture graph; limits that force trimming; the test-author filter; determinism.

## Acceptance criteria

- AC-1 A pack for a fixture leaf contains exactly the sections and items in its golden file.
- AC-2 With tight limits, items are trimmed in priority order and listed under `trimmed`.
- AC-3 A test-author pack contains no implementation bodies.
- AC-4 Equal inputs give equal digests; changing any included item changes the digest.
- AC-5 Reuse candidates above the threshold appear under `reuse_targets` with their reasons.

Standard Definition of done.

## Escalate if

A role needs information the kernel or graph cannot supply.
