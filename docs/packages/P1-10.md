# P1-10 Kernel hardening

## Goal

Fuzzing, crash-and-replay and race coverage across the whole kernel, so the P1 quality gate can be checked mechanically.

## Context

The P1 gate: vectors pass, the suite is race-clean, one hour of fuzzing finds nothing, reads stay flat, and `status` and `why` work with models off.

## Design

- Fuzz targets: codec `Decode` and `Encode`, gate envelope parsing, and operator field validation.
- Crash suite: random fault points in `Transact` across a generated workload, then `Verify` and `Replay` after each crash; the head is always a complete batch.
- `internal/kernel/hardening` holds a test that runs the whole lifecycle trace end to end through the CLI.

## Out of scope

New behaviour. Hardening only adds tests and harnesses.

## Test plan

Codex writes `checks_test.go`, asserting the gate conditions; Antigravity builds the targets and suites.

## Acceptance criteria

- AC-1 Each fuzz target runs for one hour nightly without a crasher.
- AC-2 Two hundred random crash points all recover to a complete batch that verifies and replays.
- AC-3 The full lifecycle trace passes end to end through the CLI with no model or network.
- AC-4 `go test -race ./internal/...` is clean.

## Definition of done

Standard Definition of done.

## Escalate if

A crasher or race points to a contract gap rather than a bug.
