# P4-11 purser run, first feature

## Goal

`purser run <task>` executes an approved plan wave by wave until done or blocked, and delivers one feature-bench task end to end, closed on evidence only.

## Context

P4 gate. From here Purser executes its own packages.

## Design

- `run <task> [--parallel N]` starts the scheduler for the task's approved plan in process and streams wave progress; `status <task>` shows frontier, running nodes, blocked items and budget used.
- The first feature is chosen from your feature-bench candidates; its run, evidence report and cost are committed under `bench/feature/first/`.
- `run_test.go` is an end-to-end test on a small fixture repository in replay mode.

## Out of scope

The daemon (P6-05).

## Test plan

End-to-end fixture in replay mode; the live run is your review.

## Acceptance criteria

- AC-1 The fixture task runs from approved plan to closed root in replay mode.
- AC-2 The first feature-bench task closes on evidence with no manual code edits.
- AC-3 Its evidence report and cost are committed.

## Definition of done

Standard Definition of done, plus your acceptance of the first feature.

## Escalate if

The run needs manual intervention that no contradiction or approval covers.
