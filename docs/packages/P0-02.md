# P0-02 Scope and frozen-test checks

## Goal

A Go tool, `briefcheck`, that validates package briefs and stops any pull request that writes outside its package scope or changes frozen tests.

## Context

This is the mechanical guard against the scope drift that derailed purser-main. See the plan's Ground rules.

## Design

Commands, each exiting 0 on success and 1 with a list of violations:

- `briefcheck validate` checks every `docs/packages/P*.md`: required front-matter keys, `id` equals the file name, `depends_on` IDs exist, no dependency cycles, `builder` differs from `test_author` (except `none`, and `purser` for both), `reviewer` is the test author or `you`, `merge: auto` only with `size: S` and `contract_change: false`, size L only in draft, required sections present, and ACs numbered from 1 without gaps. It implements the same rules as `tools/check_briefs.py`, which it replaces.
- `briefcheck scope --id <id>` on a `tests/<id>` branch: the diff against the merge base with `main` may touch only `tests_frozen`, `zz_stub.go` files in `scope.write` package directories, and `docs/packages/<id>.*`.
- `briefcheck scope --id <id>` on a `build/<id>` branch: the diff against the tag `frozen/<id>` may touch only `scope.write` and `docs/packages/<id>.*`; deleting stubs is allowed. Frozen paths take precedence: a path matching `tests_frozen` is never writable on a build branch, even when `scope.write` also matches it.
- `briefcheck frozen --id <id>` on a build branch: the package's `tests_frozen` files are byte-identical to `frozen/<id>`, and no other brief's frozen files differ from `main`.
- `briefcheck contracts --id <id>` fails on changes under `contracts/` unless the brief has `contract_change: true`.
- `briefcheck red --id <id>` lists the `TestACn_` functions in the package's frozen tests, fails if any AC lacks one, runs them, and passes only if every one fails.
- The ID and role come from the branch name. Other branches run only `validate`.
- Globs follow doublestar semantics, so `**` crosses directories.
- `make briefcheck ID=<id>` runs `validate`, `scope`, `frozen` (build branches) and `contracts`; `make red ID=<id>` runs `red`.
- A CI job tags `frozen/<id>` on a size S tests branch once `vet`, `briefcheck` and `red` pass. For M and L the tag is applied after your approval.

## Out of scope

No GitHub API calls and no auto-merge logic; CI and branch protection handle merging.

## Test plan

Build fixture repositories under `testdata/` with a few briefs, a `frozen/<id>` tag and stub files, then commit in-scope and out-of-scope changes on `build/` and `tests/` branches. Cover cycles, unknown dependencies, builder equal to test author, auto merge on size M, globs with `**`, and renamed files (both old and new paths count).

## Acceptance criteria

- AC-1 `validate` passes on the repository's own briefs and fails on each malformed fixture with a message naming the file and key.
- AC-2 `scope` fails when a build branch touches a path outside `scope.write` relative to `frozen/<id>`, naming the path.
- AC-3 `scope` on a tests branch allows only `tests_frozen` paths, `zz_stub.go` files in `scope.write` package directories and `docs/packages/<id>.*`.
- AC-4 `frozen` fails when a build branch modifies, deletes or renames its own frozen file relative to `frozen/<id>`, or any other package's frozen file relative to `main`.
- AC-5 `contracts` fails on a contract change unless the brief sets `contract_change: true`.
- AC-6 A renamed file is checked under both its old and its new path.
- AC-7 CI runs `make briefcheck` on every pull request whose branch matches `build/*` or `tests/*`.
- AC-8 `red` fails when an AC has no `TestACn_` test, or when any AC test passes on the stubs.
- AC-9 The freeze job tags `frozen/<id>` for a size S tests branch only after `vet`, `briefcheck` and `red` pass, and never for M or L.
