# P0-07 Quality harness

## Goal

Coverage floors, fuzzing and benchmark regression checks run automatically, so quality cannot quietly slip.

## Context

The design puts quality and stability first, and purser-main's quadratic replay must never return.

## Design

- `.coverage.yaml` sets floors: 85% for `internal/kernel/**`, 70% for everything else, plus per-package overrides that may only raise a floor.
- `tools/covercheck` reads a coverprofile and `.coverage.yaml` and fails below a floor. `make check` runs it.
- `make fuzz` runs every `Fuzz*` target for 30 seconds; the nightly workflow runs each for one hour.
- `tools/benchcheck` compares benchmark output with ratios declared in a test's comment. The first rule: snapshot read time at 100,000 events within twice the time at 1,000 events. The benchmark itself arrives with P1-02c.

## Out of scope

No fuzz targets or benchmarks of real packages; their packages add those.

## Test plan

Coverprofile fixtures above and below the floors. Benchmark output fixtures that pass and fail a ratio rule. Check that an override lowering a floor is rejected.

## Acceptance criteria

- AC-1 `covercheck` fails when any package is below its floor and names the package.
- AC-2 A floor override below the default is rejected.
- AC-3 `benchcheck` fails when a declared ratio is exceeded and passes when it holds.
- AC-4 The nightly workflow runs all fuzz targets for one hour each and fails on any crasher.

## Definition of done

Standard Definition of done.

## Escalate if

A floor cannot be met for a structural reason, such as generated code; propose an explicit exclusion instead of lowering it.
