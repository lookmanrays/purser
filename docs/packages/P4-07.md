# P4-07 Integrator, review package and reviewer

## Goal

Bottom-up integration of closed children into their module, a compact review package, an advisory reviewer, and a final evidence report built from verdicts.

## Context

Design: Verification (review package) and The engineer loop (Integrate, Verify, Report).

## Design

- Integrator: when all children of a module close, merge their worktree branches into the module branch in dependency order, run the module's integration tests through observers, and close the module on evidence.
- Merge conflicts are not resolved by a model: the conflicting node is reopened with the conflict attached.
- Review package: approved design and decisions, conformance report and observer results, diff summary by module, full diff only for flagged areas, escalations and contradictions.
- Reviewer: a fresh-context model call over the package; findings are advisory and may become new work nodes.
- Evidence report: Markdown and JSON assembled only from kernel records (verdicts, digests, commits), never from model narrative.

## Out of scope

Posting to tam (P6-04).

## Test plan

Fixture module with three closed children; a merge conflict; replayed reviewer output; report golden file.

## Acceptance criteria

- AC-1 Children merge in dependency order and the module closes when its integration tests pass.
- AC-2 A merge conflict reopens the conflicting node with the conflict attached.
- AC-3 The review package contains exactly the specified sections.
- AC-4 The evidence report matches its golden file and cites only kernel records.

Standard Definition of done.
