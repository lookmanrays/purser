# P4-09 Worker adapters

## Goal

Run module-level work on headless OpenCode sessions or Codex exec, with the same context pack and the same submit path as the leaf loop.

## Context

Design: Execution runtime (Agentic workers). The role contract stays the same whichever worker runs it.

## Design

- Adapter interface: `Start(ctx, assignment, pack, worktree) (Handle, error)`, `Wait`, `Cancel`.
- OpenCode: start its server headless in the worktree, connect it to Purser's MCP server with the assignment token, send the pack as the first message.
- Codex exec: run `codex exec` in the worktree with the pack as the prompt and Purser's MCP server configured.
- Timeouts and cancellation; the worker's transcript is stored as an artifact.
- The worker never receives credentials beyond its MCP token and its model access.

## Out of scope

Choosing which worker runs a node (P5-02).

## Test plan

Fake worker binaries that call the MCP tools; timeout; cancellation.

## Acceptance criteria

- AC-1 A fake OpenCode worker receives the pack and submits through MCP.
- AC-2 A fake Codex worker receives the pack and submits through MCP.
- AC-3 A worker exceeding its timeout is cancelled and the node is marked for retry.
- AC-4 Transcripts are stored as artifacts with digests.

## Definition of done

Standard Definition of done.

## Escalate if

A worker cannot be configured to use only Purser's MCP server for submission.
