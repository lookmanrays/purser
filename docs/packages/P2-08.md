# P2-08 Index CLI, snapshot record and benchmark

## Goal

`purser index` and `purser graph …` commands, a kernel record of each graph snapshot, and a benchmark run on your own Go and TypeScript projects.

## Context

The graph becomes evidence when the kernel records which commit it describes and its digest. The P2 gate runs on two of your repositories.

## Design

- `purser index [--full] [--repo PATH] [--graph PATH]`: incremental by default, full on first run or with `--full`; SCIP first, syntax fallback per language when SCIP is unavailable; coverage edges when `--coverage` is set.
- `purser graph symbol NAME`, `refs ID`, `callers ID`, `neighbors ID --depth N --kinds K`, `interface PKG`, `reuse --contract FILE | --symbol ID`, `stats`. JSON by default; schemas under `contracts/cli/graph/`.
- Kernel operator `graph.snapshot` (v2) in `internal/kernel/ops/graph`: planner or launcher role; fields `id`, `git_commit`, `digest`, `indexers`, `files`, `symbols`; creates a `GraphSnapshot` record. `purser index` proposes it after a successful run.
- `bench/graph/repos.yaml` lists your benchmark repositories by path and commit (you fill it in). `make bench-graph` runs a full index, then an incremental index after a scripted one-file change, and writes timings and counts to `bench/graph/results/<repo>.json`.

## Out of scope

Serving the graph over MCP (P4-08).

## Test plan

CLI golden files against the P2 fixture repositories; operator tests for role checks and field validation; the benchmark harness tested on a fixture repository with a temporary `repos.yaml`.

## Acceptance criteria

- AC-1 Each `graph` subcommand returns output that validates against its schema and matches its golden file.
- AC-2 `purser index` on a fixture repository records a `GraphSnapshot` whose digest equals `store.Digest()` and whose commit equals the repository head.
- AC-3 `graph.snapshot` from an executor binding is rejected with `forbidden`.
- AC-4 Without SCIP indexers on `PATH`, `purser index` falls back to syntax extraction and says so in its reply.
- AC-5 `make bench-graph` writes results with full and incremental timings for every repository in `repos.yaml`.

## Definition of done

Standard Definition of done. P2 gate: both of your benchmark repositories index cleanly, seeded duplicates are caught (P2-07), and incremental updates are clearly faster than full indexes.

## Escalate if

One of your repositories cannot be indexed by either SCIP or the syntax fallback.
