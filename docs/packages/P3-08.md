# P3-08 Planning CLI

## Goal

`purser task new`, `plan`, `validate`, `approve`, `reject` and `graph --test` and `--contracts`, with JSON output and stable exit codes.

## Context

Design: CLI table.

## Design

- `task new "<text>" [--criteria FILE]` creates a commitment with acceptance criteria.
- `plan <task>` runs the architect, then module leads, then the validator, and prints the bundle summary and the report.
- `validate <task>` reruns the validator.
- `approve <task>` and `reject <task> --reason` answer the pending approval as `principal:local`.
- `graph <task> --test | --contracts` prints the test or contract graph as text, DOT or JSON.

## Out of scope

tam approvals (P6-03).

## Test plan

Golden replies in replay mode; exit codes for pending, rejected and invalid input.

## Acceptance criteria

- AC-1 Each command's reply validates against its schema and matches its golden file.
- AC-2 `approve` admits the held plan; `reject` resolves it as denied with the reason.
- AC-3 `validate` exits 4 when the report has findings and 0 when it has none.

## Definition of done

Standard Definition of done.

## Escalate if

A reply needs data that the planning packages do not expose.
