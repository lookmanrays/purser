# P0-07b Quality harness: benchmark ratios

## Goal

Benchmark ratio rules run automatically, so purser-main's quadratic replay can never return unnoticed.

## Context

Split from P0-07, whose build needed about 700 lines against its budget. The tests were written and frozen with P0-07 and only renumbered here (AC-3 there is AC-1 here).

## Design

- `tools/benchcheck` reads `go test -bench` output and compares benchmarks against ratio rules.
  - It parses the output with `golang.org/x/perf/benchfmt`, which handles headers, `-benchmem` columns, sub-benchmark names such as `BenchmarkSnapshotRead/events=100000-8`, and the GOMAXPROCS suffix.
  - Rules are declared in `_test.go` comments as `// benchcheck: <target> / <base> <= <ratio>`. A comment that starts with `benchcheck:` but does not parse is an error, never skipped.
  - Each benchmark's time is the median of its `-count` samples, and a ratio exactly at the limit holds.
  - The first rule: snapshot read time at 100,000 events within twice the time at 1,000 events. The benchmark itself arrives with P1-02b.
- `make bench` runs `go test -run '^$' -bench . -benchmem -count 5 ./...` and passes the output to `benchcheck` with the rules from the repository's `_test.go` files, failing when any rule is exceeded.

## Out of scope

No benchmarks of real packages; their packages add those.

## Test plan

- Benchmark output fixtures in real `go test -bench -benchmem -count` form (headers, `PASS`, `ok` lines, sub-benchmark names). They pass and fail a ratio rule, sit exactly at the limit, and include two sample sets where the median gives a different verdict from the mean and from the last sample.
- A malformed rule comment.

## Acceptance criteria

- AC-1 `benchcheck` fails when a declared ratio is exceeded and passes when it holds, using the median of samples.

## Definition of done

Standard Definition of done.

## Escalate if

A real benchmark's output cannot be parsed by `benchfmt`.
