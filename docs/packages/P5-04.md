# P5-04 Cost metering and reports

## Goal

A `Cost` record for every model call and `purser cost <task>` by role, tier and model, including human minutes.

## Context

Design: Routing and the cost model (what Purser records).

## Design

- Kernel operator `cost.record` (v2), launcher role, batched per wave to keep the log small.
- Human minutes are recorded from approvals and contradiction answers (time between request and answer, capped) and from manual entries.
- `purser cost <task>` sums tokens, USD and human minutes by role, tier and model, and computes cost per accepted change.

## Out of scope

Provider billing reconciliation.

## Test plan

Fixture usage streams; aggregation golden files.

## Acceptance criteria

- AC-1 Every model call in a fixture run produces exactly one `Cost` record.
- AC-2 `purser cost` totals match the fixture's golden totals by role and tier.
- AC-3 Cost per accepted change counts rework attempts.

## Definition of done

Standard Definition of done.

## Escalate if

A provider's usage cannot be attributed to a work item.
