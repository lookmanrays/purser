# P5-02 Tier routing and escalation

## Goal

Choose the starting tier for each node and escalate local, then Haiku, then Sonnet, with three attempts per tier, recording every routing decision.

## Context

Design: Roles and model tiers (Escalation rules).

## Design

- Starting tier from configuration per contract kind (P5-07 later adjusts it).
- After three failed attempts on a tier, move up one tier with failures attached; past the top implementer tier, return the node to its module lead as a contract question (a contradiction).
- Kernel operator `routing.record` (v2) creates a `Routing` record per decision: work, level, tier, model, attempt, reason.

## Out of scope

Learning (P5-07).

## Test plan

Sequences of attempt outcomes through all tiers; the contradiction at the top.

## Acceptance criteria

- AC-1 A node starts on its configured tier.
- AC-2 Three failures on a tier move it up exactly one tier with failures attached.
- AC-3 Failing the top tier raises a contradiction to the module lead.
- AC-4 Every decision creates a `Routing` record.

## Definition of done

Standard Definition of done.

## Escalate if

A tier has no configured model.
