# P1-02a AC-2 looks up an approval ID absent from the wire snapshot

The SQLite dependency scope and wire integer decoding issues were resolved by #20 and #21. This note records a separate contradiction in the frozen projection test.

## Conflict

The [frozen AC-2 lookup](../../internal/kernel/projection/projection_test.go#L143) asks for this ID in `expected.snapshot_at_4.projection`:

```text
a:0998f5963f45ca09ae54848d7990117a7a583e765502b665fa7e4663aeae4589
```

The [wire fixture](../../testdata/vectors/purser-v1/wire-v1.json) gives the following ID in `ApprovalRequested.data.id` and in the sole Approval record at both revisions 4 and 8:

```text
a:19181b8d8107854127291b7431d56405d165271426f0ca411d19e61e7c542884
```

AC-2 requires an exact match to the wire snapshots. A lookup by ID must use the record identity in that snapshot.

## Evidence

- `cmp testdata/vectors/purser-v1/wire-v1.json reference/python/docs/contracts/wire-v1.json` confirmed byte identity. The Python reference checker passed all three tests.
- `git show frozen/P1-02a:internal/kernel/projection/projection_test.go` confirmed that the conflicting literal is in the frozen baseline (`f62ba0c`).
- With a local projection draft against `origin/main` at `0029c25`, `go test -v ./internal/kernel/projection -run '^TestAC2_ProjectionChecksumAndSnapshotParity$'` matched both projection checksums and passed the sorting case. Its sole failure was `p4.Record(approvalID) not found` at line 145.

## Proposed resolution

Have the test author derive the approval ID from the wire `ApprovalRequested` event in the AC-2 lookup, then approve and refreeze the corrected test baseline. Resume the builder from the approved baseline.
