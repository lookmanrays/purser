# P4-06 Test-author role

## Goal

Tests written from contracts only, compiled against stubs, proven to fail on them, and frozen by digest as obligation definitions.

## Context

Design: Verification (Test integrity). This is the role that lets Purser close its own work honestly from P7.

## Design

- Input pack holds the contract, examples, the generated skeleton and stubs, never implementation.
- Output: test files filling the skeleton. The role checks that they compile and that every test fails on the stubs.
- Frozen tests become obligation definitions: `obligation.set` with the definition digest, so any later change is a new version.
- A role that wrote a node's tests is never assigned that node's implementation.

## Out of scope

Mutation testing.

## Test plan

Replay fixtures; a generated test that passes on stubs (vacuous); the separation-of-duty rule.

## Acceptance criteria

- AC-1 Generated tests compile and all fail on the stubs before freezing.
- AC-2 A vacuous test blocks freezing and is reported.
- AC-3 Frozen tests are recorded with their definition digest.
- AC-4 The scheduler never assigns implementation of a node to the actor that authored its tests.

## Definition of done

Standard Definition of done.

## Escalate if

A contract lacks examples needed to write meaningful tests.
