# P6-05 Daemon

## Goal

`purser serve` runs the scheduler, tam sync and the MCP server in one process, and can restart at any point, deriving all state from the kernel.

## Context

Design: Execution runtime (Daemon) and Architecture (Process model).

## Design

- Components run as supervised goroutines with restart on panic and backoff.
- A local control socket lets the CLI talk to the daemon; without a daemon the CLI runs one-shot in process.
- Graceful shutdown: stop dispatching, wait for in-flight gate transactions, cancel workers, keep worktrees for resume.
- Startup: verify the store, derive running nodes from the kernel, reconcile unresolved effects, resume.

## Out of scope

ACP (P6-06) and the HTTP API for the later UI.

## Test plan

Kill the daemon at random points during a fixture run and restart; check no duplicate dispatch and no lost result.

## Acceptance criteria

- AC-1 Killed at any of 50 random points, the daemon resumes and the fixture run completes.
- AC-2 No dispatch is duplicated and no submitted result is lost across restarts.
- AC-3 The CLI works the same with and without a running daemon.

## Definition of done

Standard Definition of done.

## Escalate if

A component holds state that cannot be derived from the kernel.
