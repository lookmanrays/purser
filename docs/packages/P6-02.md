# P6-02 Intake and mapping

## Goal

tam tasks assigned to Purser in a ready status become Purser tasks, and Purser task state maps back to tam statuses.

## Context

Design: Tracker integration (Intake).

## Design

- Poll for tasks assigned to Purser's identity in the configured ready statuses; idempotent by tam task ID.
- Create a commitment whose statement and acceptance criteria come from the task; store the tam ID on it.
- Status mapping in configuration: triaged, design review, in progress, blocked, done.
- Conflicts (task edited after intake) are recorded and flagged, never silently merged.

## Out of scope

Approvals (P6-03) and reports (P6-04).

## Test plan

Fake tam with tasks in several statuses; repeated polls; a task edited after intake.

## Acceptance criteria

- AC-1 A ready task assigned to Purser creates exactly one commitment, even across repeated polls.
- AC-2 Purser status changes move the tam task through the configured mapping.
- AC-3 A task edited after intake is flagged with the change.

## Definition of done

Standard Definition of done.

## Escalate if

tam tasks lack a stable field for acceptance criteria.
