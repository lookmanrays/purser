# P4-08 MCP server

## Goal

An MCP server exposing Purser's tools to any agent: context pack, submit, contradiction and graph queries, bound to the agent's assignment.

## Context

Design: Architecture (Protocols). From P4 on, Codex and Antigravity work for Purser through this server.

## Design

- Transport: stdio for local agents and streamable HTTP for the daemon.
- Tools: `context_pack(work_id)`, `submit(work_id, commit)`, `contradiction(work_id, target, reason)`, `graph_symbol`, `graph_refs`, `graph_neighbors`, `graph_interface`, `reuse_find`.
- Each connection is bound to an assignment by a token minted when the scheduler dispatches; the binding comes from the token, never from tool arguments.
- Tool schemas are generated from the tool contracts.

## Out of scope

ACP (P6-06).

## Test plan

An MCP client in tests calling every tool; a token for another assignment; an expired token.

## Acceptance criteria

- AC-1 Every tool returns results that validate against its schema.
- AC-2 `submit` with a token for a different assignment is rejected.
- AC-3 An expired or revoked token is rejected on every tool.
- AC-4 Graph tools return the same data as the CLI for the same query.

## Definition of done

Standard Definition of done.

## Escalate if

The MCP Go SDK cannot carry per-connection identity.
