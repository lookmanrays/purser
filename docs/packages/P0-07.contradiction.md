# P0-07 Contradiction and Budget Escalation

## 1. Contradiction: `briefcheck contracts` falsely rejects build branches when `main` modifies contracts

### What is wrong

`briefcheck contracts --id P0-07` fails on `build/P0-07` with:
```
violation: contracts/ changed when contract_change is false: contracts/kernel/projection.yaml
```
even though:
1. `P0-07` has `contract_change: false` and does not touch `contracts/` at all (`git diff origin/main HEAD -- contracts/` is empty).
2. The change to `contracts/kernel/projection.yaml` was introduced on `origin/main` by commit `09d669f` (PR #23: "Split P1-02a: projection model and reducers become P1-02p") which merged into `main` after tag `frozen/P0-07` was created.

### Evidence

In `tools/briefcheck/main.go`, `Contracts()` is implemented as:
```go
// Contracts checks that changes under contracts/ relative to main are allowed only if contract_change is true.
func Contracts(repoRoot, id, branch string) (violations []string, err error) {
	b, err := findBrief(repoRoot, id)
	if err != nil || b.ContractChange {
		return nil, err
	}
	base := mainRef(repoRoot)
	if strings.HasPrefix(branch, "build/") {
		base = "frozen/" + id
	}
	out, err := runGitInDir(repoRoot, "diff", "--name-only", base, "HEAD", "--", "contracts/")
	if err != nil {
		out, err = runGitInDir(repoRoot, "diff", "--name-only", "main", "HEAD", "--", "contracts/")
	}
	for _, f := range strings.Fields(out) {
		violations = append(violations, "contracts/ changed when contract_change is false: "+f)
	}
	return violations, err
}
```
Notice:
1. The doc comment explicitly states: `// Contracts checks that changes under contracts/ relative to main are allowed only if contract_change is true.`
2. The design in `docs/packages/P0-02.md` states: `- briefcheck contracts --id <id> fails on changes under contracts/ unless the brief has contract_change: true.`
3. Step 7 of `docs/agents/builder.md` instructs the builder to: `git fetch origin && git rebase origin/main`.
4. However, on any `build/` branch, `Contracts()` unconditionally sets `base = "frozen/" + id`. When `git diff base HEAD -- contracts/` runs, any contract change merged into `origin/main` after the frozen tag was cut appears in the diff, falsely attributing the contract change to the build branch.
5. In contrast, `Scope()` in `tools/briefcheck/main.go` correctly handles rebasing against `origin/main` by filtering `mainChanged`:
   ```go
   if isBuild {
       if !slices.Contains(mainChanged, p) && !matchesAny(p, b.TestsFrozen) {
           continue
       }
   ...
   ```
6. The same issue reproduces on `build/P1-02a`.

### Proposed Fix for `briefcheck contracts`

In `tools/briefcheck/main.go`:
Change `Contracts()` to check changes relative to `mainRef(repoRoot)`:
```go
func Contracts(repoRoot, id, branch string) (violations []string, err error) {
	b, err := findBrief(repoRoot, id)
	if err != nil || b.ContractChange {
		return nil, err
	}
	base := mainRef(repoRoot)
	out, err := runGitInDir(repoRoot, "diff", "--name-only", base, "HEAD", "--", "contracts/")
	if err != nil {
		out, err = runGitInDir(repoRoot, "diff", "--name-only", "main", "HEAD", "--", "contracts/")
	}
	for _, f := range strings.Fields(out) {
		violations = append(violations, "contracts/ changed when contract_change is false: "+f)
	}
	return violations, err
}
```
Or alternatively, if diffing against `frozen/<id>`, ignore any path that is not also changed relative to `mainRef(repoRoot)` (identical to `Scope()`'s `mainChanged` logic).

## 2. Line Budget Escalation: Package P0-07 exceeds 350-line budget

### What is wrong

Package P0-07 brief defines:
`budget: {changed_lines: 350, excluding: tests}`

However, P0-07 bundles two distinct CLI tools and multiple harness components:
1. `tools/covercheck`: coverage profile parser supporting set/count/atomic modes, deduplication of repeated blocks, YAML configuration loader with strict unknown-key validation and floor validation, fuzz target discovery via `go test -json -list`, CLI runner and fuzz execution runner (~350 lines).
2. `tools/benchcheck`: benchmark output parser using `golang.org/x/perf/benchfmt`, GOMAXPROCS stripping, ratio rule comment parser, AST/source and directory scanners, median calculator, ratio verification and CLI runner (~300 lines).
3. `.github/workflows/nightly.yml`: 43 lines.
4. `.coverage.yaml`: 5 lines.
5. `Makefile`: wiring check and fuzz (~7 lines).

The full, working implementation passes 100% of frozen tests and `make check`, but totals ~705 changed lines (excluding tests and dependencies).

### Proposed Fix for Line Budget

Per AGENTS.md rule 6 ("Over the brief's budget of changed lines (tests excluded)? Stop and propose a split."):
- **Option 1 (Recommended)**: Raise the P0-07 budget to 750 lines, matching precedent set in P0-02 (PR #15, which raised the harness budget from 300 to 600 lines for its multi-command scope). Both `tools/covercheck` and `tools/benchcheck` are fully implemented, pass all tests, and have 0 lint issues.
- **Option 2**: Split P0-07 into:
  - `P0-07a` (Coverage floor & nightly fuzzing harness: `tools/covercheck`, `.coverage.yaml`, `.github/workflows/nightly.yml`, `Makefile`) with budget 400 lines.
  - `P0-07b` (Benchmark ratio regression harness: `tools/benchcheck`) with budget 350 lines.
