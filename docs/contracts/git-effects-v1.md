# Local Git effect adapter

M4-B implements `git.commit` for one dedicated, controlled local repository per launcher binding. The immutable intent is the M0 object, including typed expected and target commit identities. The single foreground broker serializes each checked release. The independent observer uses a fresh shared lease and reads native Git refs and reflogs. [M0 kernel contract](kernel-v1.md) · [Worked intent and recovery](lifecycle-v1.json)

## Trusted launcher calls

`GitRepository.initialize(git_dir, repository_id, branch, source_git_dir, initial_oid, *, candidates=())` creates a **new** private bare reftable repository. Supply the actual staging Git directory and its full raw OIDs. Initialization imports the named commits and their reachable objects by local pack, sets retention and creates the initial full `refs/heads/…` branch. A launcher retains `repo.binding` in its protected configuration. Each new process reopens `GitRepository(binding)`. The binding hashes the registered name, canonical physical path, device, inode, object format, branch, starting OID, configuration digest and fresh nonce. Its digest is anchored in the initial branch reflog entry. M4-A also records that instance with the work slot.

Inside `with repo.broker() as broker`, `broker.prepare(intent)` produces exactly `intent_digest,repository_instance,changed_paths`. It checks the resource and direct branch, old and target commit objects in the repository’s actual hash format, strict ancestry and retained history. The sorted, distinct UTF-8 paths include changes in every newly reachable commit relative to its parents or the empty root. Deletions, both ends of renames and paths modified then reverted therefore participate in authorization. A distinct descendant commit may give an empty list of paths.

`broker.dispatch(intent, attempt, authorize, *, after_authorization=None, after_write=None)` prepares again inside the held exclusive lease. The trusted callback receives these fresh preparation facts and returns `(receipt, newly_authorized)` from M4-A. Only a fresh committed release with the exact effect, attempt, intent digest and dispatching state can reach `git update-ref`. A replayed receipt returns with `issued=False`. When Git completes, the call returns `(receipt, True)`. The callback at each named boundary receives no arguments. Its caller can deterministically interrupt a process after cutoff or after Git publication. Every cutoff whose response was interrupted is independently reconciled by the ledger. A redelivered admission can be read directly from the ledger even when the already moved branch precludes preparation for a fresh release.

The native update verifies the old OID, advances the canonical direct branch to the target, and creates `refs/purser/receipts/<intent_digest>` pointing to that target in a single `start / prepare / commit` transaction. Its branch and receipt reflogs carry the same intent digest and physical attempt ID. An independent witness can count actual mutations by reading the branch reflog from the bootstrap entry through each old/new pair and inspecting their messages.

## Observation and physical scope

`repo.observe(intent, attempt)` returns the fifteen fields below. The first five identify its attribution and disposition. Both `repository_instance` and `intent_digest` use lowercase SHA-256 hex. OIDs in the native observation are raw lowercase strings.

| Fields | Meaning |
| --- | --- |
| `intent_digest,repository_instance,attempt,state,reason` | M0 semantic digest, launcher's physical instance, named physical attempt, disposition and machine reason. |
| `repository,resource,expected_old,target` | Logical repository, full canonical branch and the intent’s requested commit identities. |
| `branch_tip,receipt_ref,receipt_target` | Current native branch OID, exact derived receipt name and native receipt target. The two OID reads may be null. |
| `writer_quiescent,history_intact,matching_transitions` | Positive fence and retained-history checks. Count belongs to this particular intent **and** attempt, and is null until the chronology can be read. |

A `confirmed_happened / protected_receipt_verified` answer requires the anchored branch history, the direct protected receipt with a single matching creation entry, and exactly one matching expected-old-to-target branch transition. A later legitimate descendant of the target can be the current tip. A `confirmed_absent / quiescent_no_application` answer requires a quiescent writer, readable retained history from bootstrap, zero matching transitions, a missing protected receipt, and the branch still at the exact expected old commit. The gate checks the original physical instance and attempt before recording either result. Fresh authorization and a new physical attempt are still required for retry.

A busy writer, changed precondition, unreadable or rewritten refs, a mismatched attempt, an unfinished native lock or a substituted repository produces `pending` with a specific machine reason. History checks cover the bootstrap, monotone branch advances, all broker transaction markers and the corresponding direct receipt refs with their original single-entry histories. A legitimate later advance by another controlled writer is distinguishable from the named transaction in the native chronology.

The private directory inode carries a BSD flock. Before authorization the broker acquires its exclusive lock. The actual Git writer inherits the open-file description across exec, with hooks, remote transports and background maintenance disabled. Closing the broker’s descriptor leaves a surviving Git writer’s lock in place. The read-only observer requests a nonblocking shared lock and keeps it through all reads. Native commands change cwd to the open directory descriptor before Git starts, so renaming or replacing the registered pathname cannot redirect an already authorized write. Reftable’s one stack-list rename publishes both refs and their logs together. [Git reftable transactions](https://git-scm.com/docs/reftable#_update_transactions) · [Git update-ref](https://git-scm.com/docs/git-update-ref)

The qualified model is a trusted local launcher on the tested POSIX host, a controlled private repository, retained refs and the foreground writer protocol. Native Git lock residue after forced child death keeps the operation pending. Deliberate replacement of all protected history by its owner, untrusted executor containment, and host or storage loss have separate qualification boundaries.
