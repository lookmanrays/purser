# Decision support and local work v1

M3 adds operators to the [existing gate](work-v1.md) and event types to the original journal. Every request uses the same commitment, complete base revision and idempotent scoped receipt. Role bindings come from the local launcher.

| Operation | Fields beyond op | Admission and effect |
| --- | --- | --- |
| `assumption.create` | `id,statement,observer` | Principal or planner identifies a held premise and its independent observer. |
| `decision.record` | `id,choice,alternatives,rationale,support,triggers,supersedes` | Principal or planner selects one of the distinct textual alternatives and records a rationale. Support is a set of held assumption IDs. Triggers name the subset whose contradiction requires reconsideration. An initial decision uses null for supersedes. A replacement identifies its reconsidering predecessor, preserves its history and redirects its incoming work dependencies to the new effective decision in the same event. |
| `decision.opine` | `id,decision,opinion` | Principal, planner or current executor whose assignment depends on the decision records a new opinion. The target decision retains its state and revision. |
| `dependency.add` / `dependency.remove` | `id,support` | Principal or planner changes an outgoing dependency of the named WorkItem. Its target may be a WorkItem, Assumption or current Decision in the same commitment. Changing the basis of an existing assignment fences its generation. A work dependency on another work item requires that support to be closed. A cycle exposes its unmet prerequisites. |
| `assumption.observe` | `id,assumption,finding` | The enrolled observer's binding names that assumption as its assignment and includes `premise={artifact: bytes}`. This nonempty independent observation is retained in the existing SHA-256 artifact store. Its finding is `confirms` or `contradicts`. A first contradiction of a held assumption invalidates it. Confirmation and a contradiction outside a decision's declared triggers leave that decision effective. |
| `assignment.dispatch` | `id` | The executor bound to this current assignment asks the gate to authorize one local callback while its support and generation qualify. The admitted receipt is the local release cutoff. The foreground driver assigns a distinct proposal ID to every physical callback attempt. A result still needs its own gate admission, including when a support change followed an admitted release. |

For example, declare a decision with `{"op":"decision.record","id":"D-linear","choice":"linear","alternatives":["linear","exponential"],"rationale":"The original retry schedule is linear.","support":["A1"],"triggers":["A1"],"supersedes":null}`. Bind W2 to it with `{"op":"dependency.add","id":"W2","support":"D-linear"}` before assigning its first generation. The independent event input can be `{"op":"assumption.observe","id":"Obs-changed","assumption":"A1","finding":"contradicts"}`. The resulting `PremiseObserved` event records the commitment, ID, assumption, finding, observer and artifact SHA-256.

## Closure and explanation

From the invalidated assumption the projector follows incoming `depends_on` edges, crossing a decision on a declared trigger and deduplicating visited IDs. It records the observation on the reconsidering decisions and stale work, and keeps the affected IDs on the assumption. These changes use the observation's event revision. The gate settles previous parent closures separately under their all/any/k-of-n coverage. A formerly satisfied root returns its commitment to active if its accepted outcome no longer qualifies. Historical candidates, runs and observations stay queryable.

Current stale work has no qualifying closing evidence. The frontier exposes reconsideration and rework. After replacement, a fresh assignment clears the former candidate, increments an existing generation and requires evidence for a new result. Effective decisions enter each applicable closure basis as sorted `{id,revision}` pairs. The revision is the event that made the decision effective. Context adds `choice,support` to these pairs.

The normal CLI commands are `status`, `why ID`, `context ASSIGNMENT`, `frontier` and `replay`. Use `--revision N` for a complete historical batch on read commands. q03 lists effective and reconsidering decisions, q04 records invalidated assumptions and the IDs affected at their invalidation. On work in a commitment with decisions or assumptions, why also gives its typed support edges, candidate/criterion/witness basis and currently eligible outcome. An unaffected closed leaf therefore names the precise evidence and outcome it retained. The M2 six question rows and original event bytes remain independently readable at their original revisions.
