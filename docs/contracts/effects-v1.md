# Local Git authority and effect admission v1

M4 extends the existing proposal, receipt and event formats. Every transition uses the SQLite gate. The [M0 trace](lifecycle-v1.json) fixes the canonical intent, logical digest, protected receipt ref, successful effect witness and complete outcome digests. The initialized private repository and its bound Git worker supply the physical evidence. The gate's SQL transaction contains no Git commands.

## Operators

| Operation | Fields after `op` | Trusted caller and durable result |
| --- | --- | --- |
| `effect.require` | `id,work,slot,repository,repository_instance,resource,paths` | Principal or scoped planner declares a mandatory Git operation on this work. The new ID reserves the first logical effect, initially `required`. The slot name and its authorization ceiling are immutable across generations. |
| `grant.request` | `id,work,slot,repository,resource,paths,assignment,generation,grantee,expires_at` | Principal, scoped planner or that current executor requests a single-use human challenge. The principal or planner can also name the exact next assignment ID, generation and executor before assignment. Until that assignment exists and matches, the grant cannot be exercised. |
| `approval.answer` | `id,request_digest,decision` | Existing authenticated principal answers the exact retained request. Approval issues the named grant; denial, expiry and stale origin stay durable. An exact transport retry reads the latest origin or answer receipt. |
| `grant.revoke` | `id` | Principal revokes the grant. The event records all unresolved attempts under it at this write reservation. Revocation can follow a previously authorized writer. |
| `effect.request` | `id,intent` | The bound executor submits the exact M0 intent; its `effect` must equal the operation ID. New bindings require independent Git preparation and live assignment, exact current candidate, support, scope and grant. |
| `effect.authorize` | `id,effect` | The single broker requests a *new* physical attempt ID for the bound intent. Only a fresh durable cutoff can release its Git writer. |
| `effect.reconcile` | `id,effect,attempt` | The independent Git observer supplies the exact current attempt's source report. The ID names the new observation. Reconciliation remains available across revocation, expiry, reassignment and loss of the writer. |

The grant and slot imply `git.commit`. The resource is an exact canonical local `refs/heads/…` ref. Repository and slot names use ordinary record-ID grammar. The slot also pins the 64-hex physical repository instance established at trusted initialization. Path allowlists are nonempty sorted unique lists of exact repository-relative UTF-8 filenames. A narrowed grant must be a subset of the declared slot. Measured paths must be a subset of the grant. Distinct descendant commits can have identical trees, so the measured list can be empty.

`grant.request` and `effect.authorize` each occupy a sole-operation proposal. The original grant holds the scope and versions it read, including absent IDs. The answer and original receipt finalize together through the existing principal approval mechanism. There is no grant edit. A different grant has a different ID and requires a fresh human decision. Expiry is exclusive. At the final authorization the Store samples its trusted clock inside the write reservation after verifying the current ledger. A revocation that committed earlier prevents authorization. A separately committed revocation after authorization records the in-flight attempt and closes future authority.

## Trusted preparation, delivery and observation

The executor's binding uses its assignment ID. The broker uses `actor_id=broker:git`, role `broker` and the effect ID in its binding's `assignment`. The observer uses `actor_id=observer:git`, role `observer` and the attempt ID in `assignment`. Caller JSON supplies no trusted proof or role. The local trusted launcher attaches either of the following JSON objects to a binding.

- `git_preparation` contains exactly `intent_digest,repository_instance,changed_paths`. The protected Git source produces it after checking the logical repository, branch, expected old ref, real commit types and ancestry, and actual changed paths. The initial intent pins the measured values. The broker obtains fresh preparation **while holding its repository guard** and keeps that guard through the SQLite cutoff and Git's branch-and-receipt transaction.
- `git_observation` contains exactly `intent_digest,repository_instance,attempt,state,reason,repository,resource,expected_old,target,branch_tip,receipt_ref,receipt_target,writer_quiescent,history_intact,matching_transitions`. OIDs in the report are raw full lowercase Git IDs. The branch and receipt targets can be null. The last two facts about writer and history are booleans. The transition count is a nonnegative integer or null. The observer's source establishes physical history and provenance. The gate cross-checks the exact persisted intent, instance, attempt, branch, receipt ref, old and target identities and the evidence required by the claimed class.
- Success requires `protected_receipt_verified`, a quiescent writer, intact history, exactly one matching transition, the receipt at the intended target and an observed branch. The protected source can attribute the original transition after a later legitimate advance. Confirmed absence requires `quiescent_no_application`, quiescence, intact history, zero matching transitions, an absent receipt and the branch at the original precondition. A `pending` observation retains its reason. The gate saves the canonical report bytes in the existing SHA-256 artifact store. Work closure rechecks those bytes.

Use `purser.kernel.gate.redelivery(store,binding,proposal)` before opening Git to read a previous exact transport receipt or obtain `None`. It checks actor, proposal digest, commitment and the operation's historical role/assignment scope. It can return a finalized origin after a human answer. A broker or observer reading an existing receipt may omit the fresh Git proof. The existing public `admit` preserves the ordinary JSON receipt contract.

The protected broker calls `authorize_attempt(store,binding,proposal,*,clock=...)` inside its Git guard. It returns `(receipt, newly_authorized)`. Exactly the caller that commits a previously unrecorded admitted authorization receives true. Its receipt details contain `effect,attempt,intent_digest,state`, with state `dispatching`. Redelivery, rejection and receipt lookup never produce a fresh release. An abandoned cutoff still requires independent observation. The trusted launcher supplies the real clock outside controlled fixtures.

A different transport can submit the same bound logical intent as its own sole-operation `effect.request` and read the current disposition without reopening Git. A different payload cannot reuse that effect ID. A fresh logical ID cannot replace an unresolved dispatch, an unchanged still-eligible binding or a consumed effect for the same generation. A proven absence admits a distinct physical attempt under the original intent, with a new cutoff and live grant. A changed grant or intention needs a fresh logical binding after the former attempt settled. An undelivered binding whose authority lapsed can be retired under the SQLite write reservation. Admission versions both the old and replacement grant. A settled earlier generation remains inspectable. Same-ref exclusion uses the physical instance and logical repository name through intervening attempts, including attempts from another commitment; a stale-base diagnostic names the known ref collection.

## Reads and compatibility

q05 shows every grant with active, expired or revoked state at the selected revision and evaluation time. q06 exposes each unresolved effect, its current physical attempt and recorded `dispatching` or `pending` state. q10 offers `reconcile` even after authority has ended. A fresh `authorize_dispatch` action needs a current grant, eligible intent and free ref. The external Git preconditions are measured again before the actual cutoff. `context ASSIGNMENT [--revision N] [--as-of TIME]` shows the current assignment's scoped grants, allowed paths and required effect states. Replay and reads never contact Git.

Every declared slot stays visible in the work outcome. Its positive witness has exactly `effect,observation` and must settle the current generation, assignment and candidate. Closure, coverage and root acceptance retain their M0 basis shape. Before M4 events, required effects are empty and original projection and outcome identities stay unchanged. M4 adds empty q05/q06 arrays on those original histories. Older binaries encountering an M4 event use the existing unsupported-version failure.
