# M1 preflight · Single write path and replay

Recorded before the first product edit. Accepted M0 candidate `4460381e44f3dd42d22848bf6d82fea9a817a833`. Risk R3. Feasibility PASS for a trusted local owner on Darwin arm64, local SQLite WAL, Python 3.11.15 and Git 2.50.1. The goal here is the offline storage, admission and CLI boundary for I1/I2. No external effect or model is needed.

**Authority and impact.** The versioned [M0 contract](../../contracts/kernel-v1.md) owns the wire semantics. The append-only original event payload and hash chain own history. The sole gate derives identity, read dependencies, deadlines, dispositions and authorization. The store/reducer owns numbering, deterministic projection and atomic batch installation. The CLI binds the trusted local human, decodes/encodes messages and invokes those public interfaces. The project has no previous product implementation to reuse. Introduce only the concrete store, semantic gate, pure reducer and CLI consumers required by the frozen contract. A duplicate receipt is an existing fact and never authorizes a second mutation.

| Packet | Change surface | Boundary and falsifying evidence |
| --- | --- | --- |
| M1-A · Store and reducer | `purser/kernel/` except the admission module, plus owned store tests. Original canonical bytes, type/version handling, projection ordering, local WAL, historical snapshots and transactional replay. | Apply frozen M1 and v0 fixtures, compare head and projections. Interrupt a real transaction between multiple writes, reopen from a fresh process, and observe an old or complete new batch via a separate SQLite connection. | M1-C · Admission | `purser/kernel/gate.py` and gate tests, coordinated with M1-A's committed API. Immutable proposal identity, validation, current read dependencies, ordered operations, pending and final receipts, and principal-bound responses. | Same-ID same-digest response loss, changed digest, stale depended-on and unrelated revisions, pending approval after restart, repeated answer, partially invalid batch, concurrent proposals. Confirm externally observable outcomes from a fresh CLI on the real store. |

**Lenses.** Shared contracts and state, architecture and modularity, authorization/concurrency, durable execution and storage recovery, and tooling bootstrap. M1 trusts the local operator and demonstrates normal module/CLI write ownership. Adversarial OS isolation belongs to its separately qualified runner boundary. Wall-clock tests use a trusted injected clock at the gate interface or recorded inputs. The public CLI uses actual UTC.

The orchestrator owns shared wiring. The store worker exposes `Store.initialize/snapshot/replay/transact` and the pure event reducer. The CLI worker consumes those interfaces and the public `gate.admit` contract. M1-C starts after the store candidate is available. A worker reports a contract discrepancy before changing published meanings. The independent verifier checks the combined SHA from a clean worktree and records actual observations. No unit or fixture-only pass substitutes for a real CLI/process/SQLite boundary.
