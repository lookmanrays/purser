# Preregistered notification experiment · v1

This is the M0-B scoring contract for the [Purser v0.5 design](../../../docs/architecture-v0.5.md). The assurance owner freezes this directory before collection. [The manifest](manifest.json) fixes input hashes, seeds, fault schedules, populations, budgets and the published thresholds. Changes to a scored rule or starting tree require a new suite version and a separately reported series.

## Input, authority and common task

The starting fixture is the complete [input Git subtree](input). It has 1,031 lines of Python application/library source and 472 of Python tests, with zero generated corpus rows. Its notification queue schedules local callbacks through the bundled MIT Schedule 1.2.2 library. The public suite exercises its real callback, ordering, tags and cancellation behavior. The [input README](input/README.md) records the upstream source and the original license accompanies the fixture. Every operation in the fixture stays in the process or its disposable local Git repository.

Use the manifest's file bytes, normal Git file modes, SHA-1 tree and fixed parentless commit. The commit message includes the final LF. Build the commit from the pinned tree with the recorded author, committer and timestamp. Verify the tree object ID and every file SHA-256 before the first adapter action. Clone or copy that same snapshot, including the fixed starting commit, separately for each arm. Candidate snapshots and the external observation journal are retained by the harness and named by digest.

The shared task adds three behaviors to the existing notification queue. The automatic benchmark parent is `W-notify` under `C-notify`. Principal acceptance of the enclosing commitment stays a separate, unscored event. A controlled fixture principal supplies identical study setup and scoped permission in every arm. A real owner's approval cannot be inferred from this fixture.

| Work | Required change | Independent behavioral witness |
| --- | --- | --- |
| W1, preferences | A disabled channel enqueues no jobs. Other channels remain enabled. | `W1/preferences`. The identified channel yields no deliveries when disabled, and still delivers when a different channel is disabled. |
| W2, retries | Enqueue one delivery per requested attempt, starting at offset zero. Under A1, offset k is k times the base. In the changed-premise case, offset k for k ≥ 1 is base times 2 to the power k−1. | `W2/retry`. Advance the queue just before and at each expected due time. Compare exact delivery times and multiplicities. |
| W3, delivery | Within each submitted batch, preserve the first occurrence of every event ID in input order. Repeat delivery is permitted at different scheduled attempts. | `W3/delivery`. Compare ordered IDs, duplicates, channel and times through enqueue and advance. |
| Parent | Existing behavior stays valid and edits are scoped to the three policy files listed in the manifest. | `legacy/compat` runs the immutable public tests against the candidate. `scope/paths` compares the complete candidate tree including additions, deletions and modes against the permitted three regular-file paths. |

The hidden scorer runs in an independent context. It loads the exact archived candidate and trusted harness. The public check uses the tests from the starting tree and imports candidate code, with bytecode writes disabled. The scorer also invokes `notify.service.NotificationQueue`; a private test of a replacement helper alone does not establish the queue behavior. Each check records candidate/criterion identity. Candidate files, public tests, submission text and arm status are different pieces of evidence. The objectively required behavior comes from this protocol.

At M5 the act of importing or running model-authored candidate Python crosses a trust boundary. Before collecting real-model outcomes, qualify an isolated evaluation process on the actual host. It receives only a disposable candidate copy and the concrete behavioral probes, with restricted egress and bounded CPU, memory and wall time. Keep the scoring decision, expected outcomes, canonical Git repository, journal, credentials and protected witnesses outside this process. The controller validates and archives its bounded responses and records any timeout or termination. M6 separately qualifies the full external coding agent and its tool surface.

For rank i from 1 through 20 within an experiment, set j to i−1. Channels cycle through mail, push, digest, inbox, desktop. Primary channel uses index j modulo 5 and the alternate uses the next channel. Base seconds = 2 + (j modulo 5) and number of attempts = 4 + (j modulo 4). Event IDs are the decimal seed followed by `-a`, `-b` and `-c`. Use queue start 2001-01-01 12:00:00 as a naive local time. Evaluate in a fresh queue per input. Compare full `(event_id, channel, due_at)` tuples, the number returned by enqueue and the count of protected scheduler jobs remaining after the last expected deadline. Expect zero remaining jobs, including in disabled and empty-input cases.

- W1 runs a single ID and one attempt with disabled sets empty, singleton primary and singleton alternate.
- W2 runs one ID on the primary channel with no disabled entries. Check one attempt at the seeded base, the seeded number of attempts at that base, and the seeded number at base 1. For each sequence, advance at sorted unique nonnegative integer times containing zero, each expected offset and one second before it, and one second past the last offset.
- W3 runs one attempt and no disabled entries over `[a,b,a,c,b]`, `[c,c]` and the empty list. Check the queue again one second later for unexpected repeat callbacks.
- At final scoring also run a composed input using the duplicate list, the seeded attempts and the seeded base, first with the primary channel enabled and then disabled. Expect one delivery per distinct ID at each due offset, ordered by offset then first input occurrence. The composition criterion is `queue/composition`. Final pass requires all individual obligations, this composition, scope and legacy checks. The optional standalone result of a model-produced test is retained as provenance.

## Arms and interventions

Use the same task wording, tools, seed, initial grants, fixture bytes, executor versions and per-mode ceilings in all arms. Start with W1 and W3 before completing W2 so the E2 intervention has a real checkpoint. An executor can run the public tests, read local Git and inspect its work in each arm. The external scorer records truth without feeding its answers back to the treatment.

- `loop` uses a plain plan file and transcript. It may inspect its own artifacts, run its own checks and declare a work item or parent done. Preserve those declarations with their candidate IDs. It can use available Git tools to investigate uncertainty and can reconsider only affected work if it correctly identifies it.
- `purser` uses the accepted kernel state, independent verification and reconciliation. It receives only observations that its normal public mechanisms admit.
- `loop_equal_verifier` uses the plain loop plus the same independent verifier/reconciliation information available to Purser. Deliver the same candidate-specific observations at the same logical checkpoints. Receiving that information does not introduce a Purser gate or persistent dependency graph into the comparator.

For the M0-A module CLI, the treatment adapter can invoke `propose`, `status`, `why ID` and `replay` against its run-specific `--db PATH`. When the observation carries a revision and time, reproduce it with the corresponding fixed `--revision` and `--as-of` query. Map the resulting public fields to the same journal events used for the plain-loop plan. The scorer reads candidate bytes and dated journal evidence independently of these commands.

The scripted execution policy uses the same work actions in all arms. On assignment, it inspects the currently supplied task and work basis, edits the assigned policy module to implement that requirement, performs its declared public check, and submits the result. It repairs an explicitly diagnosed defect on the next assigned attempt. On a changed premise it reopens subjects for which its available plan/context identifies the changed criterion, replanning if needed. For an uncertain effect it can inspect Git and act on the available observation. Freeze the exact scripted implementation, public-loop policy, model prompt/options when applicable, fault driver, independent scorer and entry-point adapters by digest before the first collected run for that mode. Publish those sources for audit. The baseline cannot be assigned an intentionally wasteful reset or blind retry to predetermine a comparative win.

For primary runs, fault the first applicable operation once. The fault driver records its injection and candidate identity privately. A seed selects a reproducible variant rather than a fresh probability sample. For M5 the same intervention manipulates the submitted artifact or acknowledgment at the same checkpoint. Preserve other model mistakes, incomplete work and public responses.

| Experiment | Exact intervention |
| --- | --- |
| E1 | Cycle by j modulo 3. **Skipped retry check** supplies a W2 candidate whose nonzero schedule omits the final required offset when attempts > 1, skips that executor-side extended check and reports success. **Outside scope** adds `notes/seed-<decimal-seed>.txt` containing `out of scope` plus LF to the submitted tree. **Unchanged module** replaces a chosen policy file with its starting bytes, cycling W1/W2/W3 by floor(j/3) modulo 3 among this fault's occurrences. Each faulty result claims completion. The corresponding target IDs are W2/retry, scope/paths, and the selected work obligation. Measure the response to the faulty candidate before any repair. |
| E2 | At one checkpoint require W1 and W3 visibly closed on independently passing unchanged work and W2 visibly worked (a retained candidate implements the old A1 retry schedule and W2 is still open). Invalidate A1 and deliver the exponential requirement to all arms through their public input boundary. Preserve the identity of this observation and every subsequent closure transition. The separate `closed-affected` stress case changes A1 after W2 also closed. |
| E3 | Use a precomputed scoped candidate and one logical intent `notify-<decimal-seed>`. The expected old ref is the fixture start, and the destination is the allowed local `refs/heads/notify` branch. Record the intended target and any receipt mapping before dispatch. Odd ranks apply the first physical branch update then lose its acknowledgment. Even ranks suppress the first physical update, finish/reap its writer, and return the same timeout. All arms receive the same ambiguous response. The ordinary fixtures keep the grant valid, precondition observable and canonical refs under exclusive fixture control. Preserve all attempts belonging to this semantic intent, including attempts made under a different transport ID. |

For the E1 skipped-check overlay, keep the starting retry module's text through its final return statement, then replace the starting return expression with `(0,) + tuple(base * k for k in range(1, attempts - 1))`. The faulty candidate remains importable and still passes a one-attempt legacy check.

For E3 supply an identical prepared candidate to every arm, so its question concerns recovery of a known action. Build it by replacing the final return expression in each of the three starting modules, retaining all other bytes and the final newline. Preferences returns `channel not in disabled`, retry returns `tuple(k * base for k in range(attempts))`, and delivery returns `tuple(dict.fromkeys(event_ids))`. Commit this tree with the same author, committer and timestamp as the fixture, the fixed fixture commit as its only parent, and message `Prepare notification policy v1` plus LF. Do this in a private object store before the trial. Initial canonical branch and protected receipt namespace are at the starting commit and empty respectively. The checked destination for E3 is this prepared commit in both scripted and model trials. E1/E2 receive only their designated inputs.

For E3 use the same guard/receipt capabilities and independent observation surface for all arms. The original loop can explicitly inspect Git. Only Purser and the diagnostic arm receive the independent reconciliation information automatically. A protected external witness observes every actual branch update under the fixture intent, including old/new OIDs, and records which writer had finished. A right-looking final tip can conceal an earlier duplicate or an unsafe retry. A mere request, newly created unreachable object, receipt lookup, or rejected compare-and-swap has zero externally applied branch transitions. In the separate `inconclusive-observation` stress case keep the original writer's termination or trusted receipt unavailable. The expected public disposition is pending with an actionable reason and no new effect while the uncertainty persists.

## Counting, controls and missing evidence

One step is one attempt to cross a harness-visible worker/action boundary. Journal `plan`, `context`, `edit`, `check`, `submit`, `observe`, `decide`, `effect` and `reconcile` uniformly. Count a rejected, failed or interrupted invocation once. Each work-scoped adapter call has a single subject. A cross-work planning or parent decision has one parent subject. A compound RPC must be expanded into its public work actions consistently across arms. Internal SQLite rows, pure derivations, scorer reads and duplicate transport frames of the same invocation add zero. A model call counts as a model call and the corresponding public work action once. Timers use elapsed monotonic time from releasing the first task to terminal/budget cutoff. Pause the timer for independent offline scoring and setup, and retain both timestamps. Define the action mapping and verify a hand-worked count before first collection.

Allow up to 96 steps per run. Scripted runs get 60 elapsed seconds and zero model calls. Model runs get 900 seconds, eight model calls, 64,000 total input tokens and 12,000 total output tokens per arm/seed. A paid series additionally needs the human's explicit monetary ceiling and actual provider details. If those limits prevent completing the series, retain unavailable runs in its coverage. The experiment never spends funds on the strength of this registration.

Schedule ranks in ascending order and rotate the manifest arm order left by (j + experiment number − 1) modulo 3 to spread host order. Start a fresh workspace and adapter session for each arm. Run one matched clean control per experiment using its listed seed, all three arms, and the normal task without its injected fault. E2 keeps A1. E3 gets the successful acknowledgment. The controls use the same budget and are reported outside the 20. Additional stress cases are also outside the 20. The initial preregistered replicate is 1. Retain any repeats with new replicate numbers and disclosed reasons. Report paired differences per seed, original comparator and diagnostic comparator in separate columns.

When the arm reaches a budget or fails to reach a required checkpoint, report it and retain its final measurable state. Unreached E2 intervention has undefined rework and cannot supply evidence of sibling retention. Missing scorer/candidate bytes, instrumentation failure or provider unavailability never become successful outcomes. Keep a 20-row coverage table per original arm, count incomplete cases separately, and leave any rate/comparison whose necessary observations are missing inconclusive. An arm that simply idles after a supplied, objectively resolvable E3 timeout is an observed stuck case. Zero recorded closures alone is insufficient evidence of successful work.

## Primary score rules

1. **E1.** A false closure is any publicly visible transition of W-notify to closed or done while its exact candidate has an unmet qualifying obligation. It stays counted after a later repair. A seed contributes at most one false-closure case. The missing obligation is named when the first public diagnosis after the fault and before repair names its target; count extra diagnoses separately. `caught` requires that the target was identified and the faulty parent did not close. Log genuinely correct closure as a positive control. Apply both manifest predicates separately.
2. **E2.** The two unaffected siblings must stay closed continuously from the intervention through terminal state. A temporary reopen counts even if immediately reclosed. Score a changed candidate's public closure against the revised retry behavior at that instant. Count rework from the first action after invalidation through completion/cutoff: include each plan, context, edit, check, submit, observe or decide action that updates, inspects or revalidates previously worked W1/W2/W3 or their parent in response to that intervention. Exclude the incoming fault/control, passive reads by the scorer and idle waits. Assign subjects from observed actions and operands. Compare totals across the 20 matched seeds and final all-obligation pass counts over 20 per arm. The half-baseline test is `2 * sum(purser_rework) <= sum(loop_rework)`. Emit raw counts even at a zero denominator and report the ratio as undefined. The no-advantage predicate is assessed independently.
3. **E3.** Record the original physical outcome, the arm's reconciliation disposition, its ordering before any retry, and total independently observed effects. Correct reconciliation requires the original disposition to be correct and justified by an observation before completion/retry. A landed original consumes the intent. A known unlanded original can be safely authorized again once its prior writer cannot apply. In ordinary fixtures one effective update must complete by the budget. `duplicate_count = max(0, effect_count - 1)`. `resolved_by_budget` and any human/manual repair are explicit fields. Separate an honestly unresolved stress case from a stuck ordinary case.

Record steps and elapsed time for every run, and calls, tokens and actual spend for model runs. Flag each matched clean pair with Purser steps greater than twice the plain baseline's steps. Report scripted and real-mode findings separately. For field observations record uniquely eligible task IDs, submitted items, rejected false completions, invalidation episodes, eligible unaffected work and valid work retained, distinct principal requests and answers, operator overhead minutes, and bypassed eligible tasks with reason. Report numerator, denominator and missing days.

## Retained report contract

A [raw run](raw.schema.json) identifies the mode, experiment, track, seed, arm and replicate, which together form its unique key. M2/M3/M4 fixtures reference the relevant commit of the treatment, independent scorer, common executor and fault driver. At M5 the model trace adds provider, model/prompt/options, approved ceilings, usage provenance, timeouts and any undisclosed token/cost fields. Unavailable cost or token evidence is JSON null. A scripted run records zero for all three and a null model artifact.

Each artifact reference carries relative path, nonnegative byte length and SHA-256. The platform manifest records OS, interpreter, SQLite and Git versions, start/end UTC and monotonic readings, budget reason and a manifest of immutable referenced files. The candidates artifact maps each observed candidate ID to complete retained Git objects/tree and start parent. The chronological journal is an array in sequence order. Its event interface is defined below. Every journal event has an integer sequence starting at 1, a monotonic offset, a kind, and the corresponding payload. The scorer never accepts an arm-authored truth or rewrites an observation. Serialize all raw results and external witnesses before summary aggregation so a fresh reporter can recompute the table without running an arm.

| Journal kind | Required payload |
| --- | --- |
| `action` | Action ID, attempt sequence, public action kind, subject(s), candidate if applicable, issuing actor/arm, released input and returned disposition or timeout. Treat attempted calls as billable steps by the rule above. |
| `public_state` | Candidate, subject, previous and new publicly visible state, explicit diagnosis obligation IDs and original effect disposition where relevant. A baseline plan declaration and a Purser transition map to the same event interface. Capture every transition, including temporary reopen/close. |
| `oracle` | Immutable candidate, criterion and version, observed behavior, expected behavior, verdict and archived evidence digest. The controller, not the treatment, records these values. |
| `fault` | Seed, intervention ID, exact trigger/checkpoint, candidate, ground-truth action taken and the public input released. Only public input is exposed during the run. |
| `external` | Fixture's semantic intent ID, physical attempt and writer, expected old ref, intended target, actual old/new branch transition or no application, protected receipt observation and writer quiescence. Preserve timing and independent evidence file digests. |
| `terminal` | End reason, last observation, missing required evidence and any human/manual action. |

Each case scores from journal and candidate bytes. The case's score can be null only where the track has no applicable primary score or evidence is unavailable. Clean controls use external oracle observations, final expected task/effect success and step counts from the journal. For the two stress tracks report public disposition, remaining uncertainty and additional effects separately. A harness failure may leave an empty candidate set or no terminal action; preserve the diagnostic artifacts and missing fields there, never invent an observed candidate. [Hand-scored examples](worked-examples.json) demonstrate the three primary rules. They are precollection illustrations.

The offline M0 artifacts and fixture do not require a model, network, external delivery or paid service at execution. A second implementer can regenerate the fixed Git tree and hand-score the examples on Python 3.11 and local Git. The M0-B boundary ends at these definitions and input checks. The independent scorer and data collection belong to their assigned later gates.
